## 0. 세 줄 요약

- 두 멘토가 서로 다른 말 같지만 수렴점은 하나다. "커머스 상품등록 탐지는 레드오션이고 잠잠해지는 중이니, 더 임팩트 있는 데로 한 발 더 나가라."

## 1. 두 멘토 수렴점 (신호 강함)

세 가지를 두 멘토가 같이 말했다. 겹치는 만큼 신뢰도가 높다.

- **스코프를 줄여라.**
  - 류건희: "너무 크면 줄여라. 우리 방향대로 안 가도 된다. 꼭 이렇게 가야 한다는 아니다."
  - 신재웅: "한 발 더 나가되 하나만 정해 빠르게 가라."
- **커머스 상품등록 자체는 매력이 약하다.**
  - 류건희: "큰 커머스는 자체 모니터링한다. 작은 데는 셀러가 위험부담을 진다. 굳이 돈 주고 서비스 안 산다."
  - 신재웅: "상품 올리는 걸로는 잠잠해지는 게 맞다."
  - 함의: 우리의 "11번가 상품 상세페이지" 프레이밍이 정면으로 지적당했다.
- **식품만 고집하지 마라. 단 예시로는 의료/식약처가 임팩트 있다.**
  - 류건희: "제일 찾기 쉬운 건 의료다. 공정위가 전 업종 총괄 시작점이다."
  - 신재웅: "식품일 필요 없다. 위배 여부를 알려주는 게 본질이다."

## 2. 류건희 멘토 (기관·타겟 관점)

- **공정위가 전 업종 소비자 오인광고를 총괄한다. 여기서 시작하고, 해당 업종 기관(식약처/특허청/부동산/환경부)을 얹어라.**
- **금융은 빼라.** 제일 타이트하게 본다. 의료가 제일 쉽다.
- 이슈 예시: 특허(브랜드 사칭, 젠틀몬스터 카피 블루엘리펀트 사례), 원산지 허위표시.
- **데이터 많아 보이는 기관 위주로 하라.**
- 공정위 모니터링은 실제로 빡세다. 네이버 쇼핑 감지 사례에서 다음날 바로 공정위가 근거 요구를 꽂았다.
- **긍정 평가:** 대시보드 잘 만들었다. 내용 좋다. 온톨로지 좋다.
- **추가 제안:** 대시보드에 AI 챗봇을 얹어라.
- **UI 피드백:**
  - 검토 상세에서 원본으로 가는 URL을 더 부각하라.
  - 우측 패널 정보가 많으면 비율을 더 키워라.
  - URL이 바뀌면(다시 올리거나 하면) "바뀌었다"고 띄워라. 메타데이터를 잘 가져오고, 실제 광고 스크린샷을 보존하고 명시하라.
  - 참고: 이 UI 피드백은 우리 `PROJECT.md` §3.5 증거보존(원본 이미지 + sha256 + crawled_at) 설계와 일치한다. 방향이 맞다는 확인.
- **기획서 피드백:**
  - 가독성 높여 다듬어라. 표지, 개정이력, 시작 순서.
  - 말투를 통일하라. ~임/~다로 끝낼 거면 마침표를 찍어라.
  - 메모처럼 보이는 부분을 사업계획서 톤으로 바꿔라.
  - 기획서를 90%까지 완성하고 서비스를 다시 만들어라.
- **포트폴리오:** 발표하면 의견·데이터를 까먹는다. 그때그때 초안이라도 메모로 남겨라. 이번 차수 주제들이 포트폴리오로 써먹을 만하다.

## 3. 신재웅 멘토 (방향 + 기술)

### 3-1. 핵심 프레임: 두 갈래 중 하나

| | A. 도메인 실제문제 해결 | B. 컴플라이언스 규제검증 |
|---|---|---|
| 한 줄 | "지금 터지는 문제를 잡는다" | "이 광고가 몇조 몇항 위반인지 알려준다" |
| 대표 타겟 | AI 생성 가짜 의사/약사 쇼닥터 영상 | 중소기업, 유튜버, 기업 준법팀 |
| 근거 | 식약처가 식품표시광고법·약사법·화장품법·의료기기법 개정 추진 중인 바로 그 문제 | "사람이 다 읽으며 몇조 몇항 위반인지 보는 걸 AI로." 기업 니즈 많음 |
| 데이터 | 유튜브 숏츠 영상(1초 1프레임) + 음성 판별 | 광고 텍스트/이미지(현재 우리 파이프라인) |
| 접근성 | 영상/이미지 부담되면 펜딩하라 | 의약/화장품은 광고 공개가 의무라 접근 가능. 제조/부동산은 내부접근 어려움 |

- **"보여주고 끝나면 의미가 없다. 시정 명령을 가정하고 하고 있잖아요."** 위배됐는지, 어떻게 위배됐는지 알려주는 서비스가 본질.
- **"식품이나 의약품일 필요는 없다. 컴플라이언스 규제 에이전트."** 단 식품으로 하면 이 알고리즘/파이프라인을 그대로 활용할 수 있다.
- 규제검증으로 간다면 식품은 애매하다고 봄. **추천 = 의약, 화장품** (광고 공개가 의무라서). 제조는 내부 접근이 힘들다.
- 둘 중 하나만 정해 빠르게 가라. 규정이 다르므로 컴플라이언스 청킹·매칭이 다 다르다. 관련 법령을 다 보고 해야 한다.

### 3-2. 기술: 딥러닝보다 LLM

- **요즘 딥러닝/파인튜닝 잘 안 한다.** 자연어 처리엔 거의 안 쓴다. 시계열 데이터는 딥러닝을 태운다.
- **법령 키워드 + 허위광고 빈출 단어 가중치를 LLM에 태워라.** 모델은 flash 같은 싼 걸로. 프롬프트를 고도화해 성능을 올리는 게 실무 트렌드.
- **결과는 같다.** 딥러닝시킬 거냐, LLM에 명확히 지시해 분기를 태우냐. 분류하는 결과는 똑같다.
- 대분류 → 중분류 → 소분류 순서(계층 분류)도 프롬프트로 가능.
- **파인튜닝(LoRA/PEFT)의 이유는 둘뿐.** "돈 아끼려고, 그리고 우리가 이렇게 학습했다 보여주려고."
- **멀티모달이 흡수한다.** OCR/ViT/YOLO 따로 안 짜도 멀티모달 LLM에 "글자 뽑아달라" 하면 뽑아준다. ViT는 이미지 정보를 LLM이 뱉어준다. "YOLO 요즘 안 쓴다."
- 딥러닝 라벨링 학습은 엔지니어 영역. LLM 활용 서비스기획자로 갈 거면 데이터 확인·프롬프트 수정·컨텍스트 엔지니어링.
- **재학습 = 업데이트에 가깝다.** 분류모델 재학습 리소스는 어마어마하다. 프롬프트/가중치 고민이 낫다.
- 하네스: LLM이 한 번 실수한 걸 두 번 안 하게 프로세스를 정립해 계속 돌린다. 온톨로지 정보를 업데이트해준다.
- RAG를 부분적으로 활용 가능. 판별 지침도 LLM에 명확히 알려줘야 한다.
- 비용: 학습용으론 괜찮다. 후자(LLM)가 낫다. 한 달에 만원도 안 나온다. 챗지피티 무료/5달러 등록으로 학습용 API 사용 가능. 이미지 태우는 건 무리일 수 있음.

### 3-3. 데이터·크롤

- robots 크롤링이 찝찝해도 **공익성이 있으면 괜찮다.** 실제 B2B 들어가면 MOU/협의 필요.
- 요즘은 합성데이터를 쓴다. RLHF로 사람과 유사하게 라벨링시킨다.
- 가이드라인을 치밀하게 만들고 사람이 검수한다. 기준 미달분(예: 30%)은 다시 돌린다.

## 5. 이 피드백이 우리 확정 결정에 주는 충격 (정리, 실행 아님)

- **간판/지향범위 (`PROJECT.md` §1):** "이커머스 부당광고 판정" → "규제 컴플라이언스 검증". 커머스는 데이터 소스로 격하. **변경 검토 필요.**
- **판정 방식 = VLM (§2-1):** 유지. 오히려 강화.
- **DL 코어 = 선생-학생 지식증류 (§2-2):** 신재웅과 정면충돌. 재정렬 필요. → `기술선택_비용성능_분석.md`.
- **크롤 = 11번가 (§2-3):** 유지 가능. 단 의약/화장품 광고 소스 추가 검토.
- **레퍼런스/온톨로지:** 그대로 핵심 자산. B 방향에서 더 중요(조항 청킹·매칭 = RAG).
- **② 이미지유형 CNN (§2-2):** 명분(DL 요건)이 사라졌고 멀티모달이 흡수. 제거 검토.
