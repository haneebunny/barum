# 미국 수출 프리플라이트 공통 OCR 재사용안 — 진행 보류

> 기록일: 2026-08-24  
> 상태: **보류**  
> 범위: 국내 검증 OCR 결과를 미국 수출 프리플라이트에 재사용하는 구조

## 1. 논의 요지

국내 검증에서도 이미지 OCR을 수행하므로, 미국 수출 프리플라이트가 같은 이미지를 다시 OCR할 필요가 있는지 검토했다.

결론은 다음과 같다.

- 이미지 OCR은 한 번만 수행한다.
- OCR 결과를 국내·미국 판정기가 함께 사용하는 공통 결과물로 보존한다.
- 국내 판정 결과 리포트(`CheckReport`)를 그대로 넘기지는 않는다.
- 국내 판정에서 합법으로 분류된 문구가 미국 판정에서 필요할 수 있으므로, 미국에는 국내 findings가 아니라 **OCR로 읽은 전체 원문·위치·전성분**을 넘긴다.

## 2. 재개 시 목표 구조

```text
이미지
  ↓ OCR 1회
공통 OCR Snapshot
  ├─ 국내 판정 → 국내 리포트
  └─ 미국 판정 → 미국 프리플라이트 리포트
```

예상 데이터 구조:

```python
OcrSnapshot(
    sentences=[...],
    ingredients_raw="정제수, 징크옥사이드, ...",
    tiles_ok=...,
    tiles_failed=...,
    source_image_sha256=...,
)
```

국내 판정과 미국 판정은 같은 `sentences`를 사용하되, 규정 레퍼런스와 판정기만 다르게 적용한다.

```python
kr_report = run_kr_judge(snapshot.sentences, ...)
us_report = run_us_judge(
    snapshot.sentences,
    ingredients=snapshot.ingredients_raw,
)
```

## 3. 현재 코드와의 차이

현재는 다음처럼 국가별 OCR 경로가 분리되어 있다.

- 국내 OCR: `backend/src/barum/preprocess/ocr.py`
  - 문장과 위치를 추출한다.
  - `ingredients_raw`를 별도 구조화해 반환하지 않는다.
- 미국 OCR: `backend/src/barum/preprocess/us_ocr.py`
  - 문장과 위치를 추출한다.
  - 전성분을 `ingredients_raw`로 별도 추출한다.
- 미국 파이프라인: `backend/src/barum/pipeline.py`의 `run_us_sunscreen_check`
  - 현재 이미지가 들어오면 미국 전용 OCR을 다시 수행한다.

따라서 재개할 때는 국내 OCR에 전성분 필드를 단순히 덧붙이는 것보다, 국가에 종속되지 않는 `OcrSnapshot` 또는 동등한 내부 계약을 먼저 만드는 것이 안전하다.

## 4. 보류 사유

- 현재 미국 프리플라이트 데모 범위는 자외선차단·SPF 최소보장으로 한정되어 있어, 공통 OCR 구조 개편이 당장 데모에 필수는 아니다.
- 국내 OCR 응답 계약을 바꾸면 국내 판정·저장·테스트·프론트 영향 범위를 함께 점검해야 한다.
- 전성분 추출 품질, OCR 실패 타일, 이미지 해시·캐시와 국가별 재판정 수명주기를 먼저 설계해야 한다.
- 현재 미국 전용 OCR은 전성분 추출 문제를 해결하기 위한 실용적인 우회 경로로 동작하고 있으므로, 보류 중에는 해당 경로를 유지한다.

## 5. 재개 시 확인할 것

- [ ] 공통 OCR Snapshot의 스키마와 저장 위치 결정
- [ ] 전체 OCR 문장·위치·전성분·실패 타일을 결과 리포트와 분리해 보존
- [ ] 국내 `/check`가 OCR Snapshot을 만들고 미국 검증이 이를 참조하는 API 흐름 설계
- [ ] 같은 이미지에서 국내·미국 판정을 연속 실행할 때 OCR 재호출이 발생하지 않는지 테스트
- [ ] 수동 전성분 입력이 OCR 전성분보다 우선하는 정책 유지
- [ ] OCR 실패 시 `성분정보_확인불가`와 `OCR 실패`를 구분해 표시
- [ ] 기존 국내 OCR 회귀 테스트와 미국 프리플라이트 테스트 보강
- [ ] 국가 전환 시 동일 원문·동일 위치를 사용하는지 프론트 플로우 검증

## 6. 현재 결정

이 아이디어는 **방향성으로 기록만 하고 구현은 보류**한다. 현재 미국 프리플라이트는 `POST /check/us-sunscreen`과 미국 전용 OCR 경로를 유지한다.
