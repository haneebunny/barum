# 전성분 파일 업로드 API (2026-08-24)

> 담당: 백엔드6. PM 요청 — create 모드에서 성분 20~30개를 한 줄씩 손으로 치는 게
> 지옥이라 파일(xlsx/csv/txt) 업로드로 대체한다.

---

## API

```
POST /uploads/ingredients
multipart, 필드명 file, 파일 하나

200:
{
  "rows": [{"name": "나이아신아마이드", "amount": "3%"}],
  "warnings": ["5행: 함량이 비어 건너뛰었습니다"]
}

415 지원하지 않는 확장자/형식
422 빈 파일, 또는 파일 자체를 못 읽음(헤더 없음·손상)
413 5MB 초과
```

저장은 안 한다. 파싱 결과만 즉시 돌려주고 프론트가 `ingredient_amounts`에 채운다.
제품사진 업로드(`/uploads/product-photo`)와 달리 나중에 id로 다시 참조할 이유가
없어서 "먼저 올려 id를 받는" 패턴을 안 따랐다.

**프론트 계약**: multipart 필드명은 `file`이다. PM 요청서엔 응답 스키마만 못박혀
있어 필드명은 이번에 정했다 - 냐냐와 맞춰야 한다.

## 파싱 규칙

### xlsx

- 이름에 `참고`가 들어간 시트는 후보에서 아예 뺀다(식약처 고시 기준표 같은
  참고용 시트가 진짜 성분표처럼 보여서 위험하다)
- 남은 시트 중 이름에 `전성분`과 `함량`이 다 들어간 걸 먼저 시도한다. 없으면
  **나머지를 원래 순서대로 훑어서 실제로 헤더(성분명·함량 열)가 있는 첫 시트를
  쓴다.** "없으면 첫 시트"를 문자 그대로 하면 안내 시트(`0_안내`)를 잘못 고를 수
  있어서 이렇게 바꿨다
- 헤더 행은 최대 15행까지 훑어서 찾는다. 열 위치는 **이름으로** 잡는다(순번·비고가
  섞여 있어 "첫 두 열"로 가정하면 깨진다)
- 예시행(`비고`에 "지우고 채우세요"·"예시" 같은 말이 있는 행)은 경고 없이
  건너뛴다 - 사용자 입력이 아니라 양식 안내다
- 완전히 빈 행도 경고 없이 건너뛴다 - 양식에 으레 있다
- 성분명·함량 중 하나만 빈 행은 **엑셀 실제 행 번호**와 함께 경고한다

### csv / txt

- `성분명,함량` 두 칸이 기본. 탭 구분도 받는다
- 구분자 없이 붙여 쓴 것도 받는다(`나이아신아마이드 3%`) - 끝의 함량 표기를
  정규식으로 뗀다. 범위(`0.2~0.5%`)·단위(`2,500 IU/g`)도 받는다
- **끝의 함량부터 먼저 뗀다.** 콤마 분리를 먼저 하면 `2,500 IU/g`의 천단위
  콤마를 필드 구분자로 오해해서 `비타민D 2` / `500 IU/g`로 잘못 쪼개진다
  (테스트로 잡아서 순서를 바꿨다)
- `성분명`·`함량`이 둘 다 들어간 줄은 헤더로 보고 건너뛴다
- 빈 줄은 조용히 건너뛴다
- cp949(메모장 기본 저장 인코딩)도 읽는다

### 공통

- 200행 상한. 넘으면 앞 200건만 읽고 경고 하나를 남긴다
- 확장자로 파서를 정한다. content-type은 브라우저·OS마다 제각각이라(csv를
  `application/vnd.ms-excel`로 보내는 경우도 흔하다) 명백히 엉뚱한 값만 걸러내는
  보조 신호로만 쓴다
- 5MB 상한. 큰 파일로 서버를 물고 늘어지지 않게

## 남은 것

- 진짜 xlsx 손상 파일(회사에서 자른 파일 등)로 수동 스모크는 안 해봤다. openpyxl이
  못 여는 걸로 시뮬레이션한 테스트만 있다
- 함량 표기 검증(단위가 유효한지 등)은 안 한다 - 원문 표기 그대로 통과시킨다는
  `IngredientAmount` 설계를 그대로 따랐다
