# 판정로직 고도화, 어떻게 진행했고 어디서 틀렸나 (2026-08-20 회고)

> 담당: 도도(2대). 하루치 작업의 회고다. **잘한 것보다 틀린 것을 먼저 적는다** —
> 틀린 쪽이 다음에 반복될 위험이 있고, 발표 소재로도 그쪽이 정확하다.
> 상세 진행 기록: [2026-08-20_판정로직_고도화_로그.md](2026-08-20_판정로직_고도화_로그.md)

---

## 1. 고도화를 어떻게 돌리고 있었나

기본 루프는 이랬다.

```
정답셋(963문장)에 규칙집을 스윕 → 못 잡은 문장·잘못 잡은 문장을 본다
  → 그 문장을 잡을 규칙 후보를 만든다 → 다시 스윕해 회귀 확인 → 채택
```

도구는 `scripts/rule_sweep.py`다. `match_rule()`만 반복 호출하는 순수 로컬 연산이라
API 비용이 0이고 몇 초에 끝난다. 규칙집을 고칠 때마다 "기준 대비 뭐가 바뀌었는지"를
본다. 지표는 세 가지를 봤다.

- **규칙 단독 위반탐지** (정답=위반인데 규칙이 violation으로 잡은 수)
- **규칙 오탐** (정답=합법·대상외인데 violation으로 잡은 수)
- **증발** (판단이 필요한 라벨이 legal_allow·out_of_scope로 확정돼 VLM에도 안 가는 수)

이 루프 자체는 잘 돌았다. 하루에 증발을 7건 → 2건으로 줄였고 오탐은 0건을 유지했다.

**문제는 루프가 아니라 후보를 어디서 찾느냐였다.**

---

## 2. 틀린 것 — 정답셋에 맞춰 방어하고 있었다

### 무슨 일이 있었나

팀장이 물었다.

> "이런식으로 하나하나 키워드를 잡아주는 방식이면 우리가 갖고 있는 테스트에 맞춤으로
> 방어하는 거잖아. 이걸 고도화라고 할 수 있어?"

확인해보니 맞았다. 그날 추가한 키워드들의 정답셋 매칭 건수다.

| 추가한 것 | 정답셋 매칭 | 지표 변화 |
|---|---|---|
| 저자극·완료 마커 | 4건 | 증발 −4 |
| 비사보롤 | 1건 | 증발 −1 |
| 탁월한 | 1건 | **0** |
| 개기름(진행하려다 중단) | 2건 | — |

"개기름"을 규칙에 넣어도 "떡짐"·"기름기"·"번들거림"은 여전히 못 잡는다.
**표본에 있는 표현만 방어하는 구조**였다.

### 더 나쁜 건, 내가 신호를 만들어 놓고 안 읽었다는 것이다

"탁월한"을 추가했을 때 스윕 수치가 **0건도 안 움직였다**(그 문장이 이미 다른 키워드로
잡히고 있어서). 나는 PR 본문에 이렇게까지 썼다.

> ⚠ 이 변경의 값어치는 정답셋 밖의 커버리지지 지표 개선이 아닙니다. 지표로 포장하지 않았습니다.

**그리고 그대로 다음 키워드로 넘어갔다.** 경고를 직접 써 놓고 경고로 읽지 않았다.

### 같은 구조가 그날 세 번 반복됐다

| # | 내가 만든 신호 | 내가 한 것 | 누가 읽었나 |
|---|---|---|---|
| 1 | "탁월한" 0건 변화 + "지표로 포장하지 말 것" | 다음 키워드로 진행 | 팀장이 물어서 멈춤 |
| 2 | PR에 "963셋에 없는 표현은 스윕으로 검증 불가"라고 씀 | **오탐 쪽에도 적용된다는 걸 놓침.** 스모크 테스트를 한 방향으로만 만듦 | PM이 실측으로 오탐 4건 발견 |
| 3 | 내 오탐 탐침이 찰과상·튼살을 걸러냄 | **"내가 지어낸 문장이 부실했다"며 지움** | PM이 더 자연스러운 문장으로 재현 |

**지표·규율·한계 서술을 만들어두는 것만으로는 아무 일도 안 일어난다.**
만든 사람이 자기 작업에 적용하지 않으면 그냥 문장이다. 특히 **자기가 만든 신호일수록
합리화하기 쉽다** — 내가 만든 탐침이니 내가 "문장이 부실하다"고 판단할 수 있다.

---

## 3. 구분은 필요하다 — 같은 날 구조적인 것도 나왔다

전부 과적합이었던 건 아니다. 값어치가 확실한 것들은 성격이 달랐다.

- **평가 골드셋이 낡아 라벨 40%가 어긋나 있던 것**을 찾아 교체했다(ver1 → ver2).
  같은 시스템인데 지표가 62.5% → 81.0%로 나왔다. **성능 개선이 아니라 측정 오차 제거다.**
- **grounding 문서가 전부 "무엇이 위반인가"뿐이고 "무엇이 합법인가"가 하나도 없던 것**을
  찾았다. 그래서 식약처 인정문구("피부의 미백에 도움을 준다.")를 3개 다 위반으로 찍고
  있었다. 법이 정해준 문구를 우리가 의심스럽다고 찍던 셈이다.
- **합법 강등이 과장 표현을 통째로 새게 하던 결함**을 양방향 측정으로 잡았다.
- **반복측정·문장단위 안정성 지표**를 도구화했다.

### 차이는 질문이다

| 질문 | 나온 것 | 성격 |
|---|---|---|
| **"왜 이렇게 동작하지?"** | 위 네 가지 | 표본과 무관, 정답셋 밖에서도 통함 |
| **"어떤 문장을 틀렸지?"** | 키워드들 | 과적합 위험 |

그래서 앞으로 규칙 후보를 낼 때 **[구조] / [표본]** 출처를 표시하기로 했다.
습관에 맡기면 또 놓칠 것 같아 감사 도구가 실행할 때마다 출처를 출력하게 했다.

## 4. 방향을 어떻게 바꿨나 — 테스트 기준에서 팩 기준으로

`scripts/pack_coverage_audit.py`를 만들었다. **정답셋을 안 본다.** 레퍼런스팩이
명시한 표현을 전부 뽑아 규칙집과 대조한다(비용 0).

```
팩 §1에서 추출한 표현: 148건
규칙집·동의어에 등재됨:  61건
미등재:                87건  ← 59%
```

발모·육모·탈모방지, 다이어트·체중감량·V라인, 셀룰라이트·튼살·습진, 근육이완·면역강화,
호르몬분비촉진, 코스메슈티컬 — **전부 우리 정답셋에 없는 표현이라 테스트 기반으로는
영원히 못 찾을 것들이었다.**

---

## 5. 그런데 그 방향으로도 또 틀렸다

팩 기준으로 바꾼 뒤 38개를 한 번에 추가했는데, **PM이 실측으로 오탐을 두 번 잡아냈다.**

```
violation | 올리브영 드럭스토어에서 만나보세요      ← "드럭" 부분일치
violation | V라인 쉐이딩으로 입체감을 살려보세요     ← "V라인"
violation | 찰과상 부위는 피해서 발라주세요        ← 안전 안내를 확정 위반으로
```

원인이 세 겹이었다.

1. **커버리지 테스트를 한 방향으로만 만들었다.** "걸려야 할 문장"만 확인하고
   "걸리면 안 되는 문장"은 안 봤다.
2. **팩 표의 비고(예외) 열을 안 읽었다.** V라인의 비고에 "색조 제품류 '연출한다' 표현
   함께 시 제외"가 있었다. 그리고 **그 비고를 버린 건 내가 만든 감사 도구였다** —
   스크립트에 "비고·예외는 조건 설명이라 표현이 아니다"라고 써 있었다.
3. **별표1만 보고 별표2(실증대상)를 안 봤다.** 셀룰라이트가 별표1에 있어 확정 위반으로
   넣었는데, 별표2에 "일시적 셀룰라이트 감소"가 있어 조건부였다.

정정 후: **1호 violation 72 → 53건, needs_review 11 → 24건.** "애매하면 검토필요"라는
우리 원칙에 훨씬 맞는 분포가 됐다. 그리고 도구가 이제 조건을 같이 찍는다.

## 6. 그래서 지금 어떤 수치를 쓸 수 있나

**가장 중요한 사실: 라벨된 홀드아웃이 없다.** `data/holdout_B.xlsx`(57행)·
`data/goldset_A.xlsx`(63행)가 만들어져 있는데 **라벨 칸이 0건 채워져 있다.**
963셋도 42문장 골드셋도 전부 튜닝에 쓰였다.

| 구분 | 수치 | 이유 |
|---|---|---|
| **못 씀** | 증발 7→2, 규칙 단독 8/16, 62.5%→81.0%, **규칙 오탐 0건** | 전부 in-sample. 오탐 0건도 오탐 내는 후보를 계속 기각해온 결과다 |
| **살아남음** | 문장 단위 안정성 90.5%, 실행 편차 폭 | **정답 라벨을 안 본다.** "정확도"가 아니라 "재현성" |
| | 위조증빙 대조(위조 2건 격상/진짜 1건 유지) | 에스코 원본 이미지 실측. 표본 3건이라 "동작 확인" |
| | 인정문구 3건 오탐 해소 | 팩(고시 2023-61호 별표4)에서 나옴 |
| | 팩 미커버 87/148건 | 정답셋을 아예 안 봄 |
| **재측정 필요** | prescreen A/B 15.0→18.7 | 방법론은 건전, 모집단만 in-sample |

**발표에 "규칙 고도화로 탐지율 개선"이라고 쓰면 안 된다.** 규칙 단독 위반탐지는
8/16에서 여러 라운드째 안 움직였다.

## 7. 서사 주의 — "우리 규율이 우리 결함을 잡았다"는 과장이다

정확히는 **측정 규율이 신호를 만들어냈지만, 그 신호를 읽어낸 건 사람이었다.**
세 번 다 그랬다. 지표를 만들어 두는 것만으로는 부족했고 읽는 사람이 필요했다.

발표에 쓴다면 이 구분을 살리는 편이 정직하고, 이야기로도 더 강하다.

---

## 8. 규칙으로 남긴 것

1. 규칙 후보는 **어느 질문에서 나왔는지** 표시한다([구조] / [표본]).
2. 팩 표를 쓸 때 **비고(예외) 열을 반드시 같이 읽는다.**
3. **별표1만 보고 별표2를 안 보면 놓친다.**
4. 팩 표현은 **파싱 조각이 아니라 원문의 완전한 형태로** 넣는다.
   ("가려움"은 정답셋 6건이 전부 법정 주의사항 문구였다)
5. **짧은 한국어 키워드는 더 긴 합성어에 걸린다.** ("드럭"→"드럭스토어")
6. 커버리지 테스트는 **반드시 양방향**으로 만든다.
7. **"이 변경은 지표로 검증 못 한다"고 쓰게 되면 거기서 멈춘다.** 그 문장은 경고다.
8. **탐침이 걸리면 문장 탓을 먼저 하지 않는다.** 걸린 건 남기고 더 자연스러운
   문장으로 다시 재서 확인한다.
