# 오염 안 된 홀드아웃, 만들 수 있나 (2026-08-20 조사)

> 담당: 도도(3대). ablation study용 clean 홀드아웃을 만들 수 있는지 **모수만 확인**한 기록.
> 팀장 지시로 1단계(원재료 수집)에서 멈췄다. 층화표본·라벨링·사용이력은 안 만들었다.
> **결론: 지금 재료로는 못 만든다. 왜 못 만드는지가 이 문서의 내용이다.**

## 왜 필요했나

발표에서 ablation(하네스 요소를 하나씩 끄며 기여도 측정)으로 고도화를 증명하려면 튜닝에
안 쓴 평가셋이 필요하다. 그런데 **지금 있는 셋이 전부 오염돼 있다.**

- 963셋: `rule_sweep`으로 규칙집 튜닝하며 전수로 훑음
- 42문항 골드셋: 반복 사용
- 119문항 프롬프트 홀드아웃: 프롬프트 A/B 전용이고, **규칙 변경에 대해서는 홀드아웃이 아니다**

## "안 읽은 이미지"와 "안 쓴 상품"은 다르다 (제일 중요)

미OCR 이미지가 놀고 있으니 거기서 뽑으면 된다고 봤는데, **상품 단위로 갈라 보니 아니었다.**

| | |
|---|---|
| 남은 이미지 | **222개** (jpg/png 205 + gif 17. 301개 파일 중 79개는 이미 읽음) |
| ├ **이미 라벨 있는 상품**의 다른 이미지 | **190장** (20개 상품) |
| └ **정답셋에 전혀 없는 상품** | **32장** (4개 상품) |

**190장은 쓸 수 없다.** 같은 상세페이지는 슬로건·성분표·인증 문구가 이미지마다 반복된다.
그 상품 문장으로 규칙집을 고쳤으니 거기서 뽑은 문장은 "처음 보는 문장"이 아닐 수 있다.

## 32장을 실제로 읽어 봤다 — 화장품은 1개 상품뿐

`scripts/build_clean_holdout.py`. 4분·약 7만 토큰. 963셋 중복 6건·페이지 내 중복 32건 제거 후
**335문장**이 나왔는데, 상품별로 열어 보니 이랬다.

| 상품 | 문장 | 정체 |
|---|---|---|
| 8143645984 | 222 | **선풍기**(저소음·3600mAh·BLDC 모터·풍속 5.2m/s) |
| **9468523524** | **109** | **화장품** — 삼육오:메디 미백 기미 개선 크림 |
| 9533932575 | 4 | 전자제품 매입 광고 |
| 9536106101 | 0 | 문장 없음 |

**정답셋에 안 쓰인 상품 4개 중 3개가 비화장품이었다.** 정답셋이 화장품만 골라 라벨링했으니
남은 쪽이 비화장품으로 쏠린 건 자연스러운 결과다.

**쓸 수 있는 재료는 109문장.** 963셋 분포(위반 1.6%)를 적용하면 위반 2건 수준이라 ablation에는
얇다. 다만 미백·기미 크림이라 밀도가 평균보다 높을 수는 있다(라벨링 전엔 모른다).

원재료는 `backend/data/clean_holdout_raw.jsonl`에 있다(gitignore).

## 라벨링 주체 — LLM이 붙이면 순환논증이 된다

팀장 결정은 "새 라벨 가이드라인을 안 만든다"였는데 그건 **기준**에 대한 답이지 **주체**가 아니다.

**LLM이 라벨을 붙이면 ablation은 "우리 모델이 우리 모델과 얼마나 일치하나"를 재게 된다.**
심사위원이 "그 정답은 누가 만들었나요"라고 물으면 지금 오염 문제와 같은 자리로 돌아간다.
963셋의 값어치는 사람이 사유까지 적어 만든 데 있다(검토필요 160건 전부에 `검토필요_사유`).

팀장이 B안(LLM 초벌 + 사람 검수, 프로덕션과 다른 모델 2개로 독립 초안 — 2026-08-15 선례)을
확정했으나, **위 재료 부족 때문에 실행 전에 중단했다.**

## 다음에 만들 사람이 알아야 할 것

1. **모수는 다시 안 재도 된다.** 깨끗한 상품 4개 32장 → 화장품 109문장이 전부다
2. **진짜 clean을 원하면 새 크롤이 필요하다.** 기존 풀에서는 더 안 나온다
3. 190장으로 넓히려면 **문장 단위 근사중복 제거**가 전제고, 그래도 규칙 변경에 대한
   홀드아웃 강도는 약하다
4. 라벨링은 **사람이 관여해야** ablation 근거가 된다

## 부수로 건진 것 2건

**① 선풍기 222문장은 버릴 재료가 아니다.** 상품 단위 대상외 게이트(`check_product_scope`)를
검증할 재료다. 판정 정확도 표본에서는 빼되 **게이트 회귀용으로 남길 값이 있다.**
[[barum-non-cosmetic-product-gap]](짜개 사건)과 같은 계열이다.

**② 통짜 OCR은 긴 이미지에서 실패한다.** 32장 중 6장이 JSONDecodeError였고 3장은 재시도해도
반복 실패했다. **전부 4400px 넘는 이미지**(1.6~1.9MB)로, 응답 JSON이 잘린다.
**운영 경로(타일 분할)로 돌리니 3장 다 성공**했다(+32문장). 스크립트를 운영 경로로 고쳤다.

⚠ 시연 점검에서 본 OCR 실패(㉕)와는 **원인이 다르다.** 그건 짧은 이미지에서도 간헐적으로
났고 재현이 안 됐다. 이건 긴 이미지에서 재현된다. 섞어 보지 말 것.
