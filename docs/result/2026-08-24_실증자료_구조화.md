# 실증자료 구조화 + 임상 카드 이미지 누락 (2026-08-24)

> 담당: 백엔드6. 발단은 프론트가 `clinical_bar_compare` 템플릿을 만들려다 멈춘 것.
> 두 건을 같이 다룬다. 뿌리가 같다: **임상 카드가 제대로 안 나오고 있었다.**

---

## 1. 왜 프론트가 못 만들었나

레이아웃 어휘집(`_vocabulary.json`)은 이렇게 요구한다.

```
clinical_bar_compare  : bars[{label, before_pct, after_pct}], footnote
clinical_photo_compare: photo_before, photo_after, stat_label, footnote
```

백엔드가 실제로 주던 것.

```python
class Section:            # models.py
    text: str             # "다크스팟 개선 87% (8주), 유어랩 피부과학연구소 시험. 20명 대상"
    table_rows: ...|None  # table_info 전용, 임상엔 안 채움
```

**`before`가 애초에 없다.** 입력(`ClinicalEvidence`)은 결과값 하나만 받는다. 제품사진도
`product_photo_ids` 평면 목록이라 전/후 구분이 없다.

그래서 이 상태로 템플릿을 만들면 방법이 둘뿐이었다.

1. 문장에서 정규식으로 숫자를 긁는다 → `"4주 후 2.1배"` 같은 표기에서 깨진다
2. **`before`를 지어낸다**

2번이 이 프로젝트가 잡으려는 바로 그 행위다. 그것도 실증자료 카드에서.

### 선택지와 결정

| 안 | 내용 | 판정 |
|---|---|---|
| 가 | 있는 값을 구조화해서 넘기고 **수치강조 카드**로 축소 | **채택** |
| 나 | 입력에 before/after 필드를 추가해 진짜 막대비교 | 기각(발표 3일 전 스코프 증가) |
| 다 | 폴백 유지(배경 + 문단) | 최후수단으로 남김 |

PM 승인(2026-08-24). 프론트도 독립적으로 같은 결론(2번=수치강조 축소)에 도달했다.

## 2. 무엇을 바꿨나

**입력 모델을 그대로 실어보낸다.** 새 출력 모델로 옮겨 담지 않았다.

```python
class Section:
    clinical_stat: "ClinicalEvidence | None" = None   # 실증자료 섹션일 때만
class ContentCard:
    clinical_stat: ClinicalEvidence | None = None
```

옮겨 담으면 그 사이에 값을 가공할 여지가 생긴다. 같은 객체를 그대로 흘려서
**"화면에 뜨는 수치 = 사업자가 친 수치"를 구조로 보장**한다.

`text`는 그대로 둔다. 구버전 프론트는 지금처럼 문장으로 렌더하고, 새 프론트만
수치를 골라 쓴다. 화면이 안 깨진다.

### 프론트 계약 (냐냐)

**`layout_type`이 아니라 `card.clinical_stat` 유무로 분기할 것.** 계획기가
`clinical_bar_compare`를 고르든 `section_statement`를 고르든 우리가 줄 수 있는 건
단일 수치라 유형별로 갈라봐야 그릴 게 같다.

```
claim       "다크스팟 개선"   ← 라벨
value       "87%"            ← 크게
period      "8주"            ← 각주
institution "유어랩 피부과학연구소"  ← 각주
note        "20명 대상"       ← 각주
```

`value`는 자유표기다. `"87%"`도 `"4주 후 2.1배"`도 온다. **퍼센트로 가정하고
막대 길이를 계산하면 안 된다.**

## 3. 같이 고친 것: 임상 카드 이미지가 1장만 나오던 문제

`generate_module_images`에 `clinical_image_done` 게이트가 있었다. 2026-08-20 당시
"실증자료 섹션은 하나만 나온다"는 가정에 맞춘 것인데, 자료 1건=섹션 1장으로 뒤집히면서
(2026-08-23) 가정이 깨졌다. 게이트만 남아 두 번째 임상 카드가 **글만 있고 이미지가 빈**
채로 나왔다. 스킵 사유 문구도 사실이 아닌 채 남아 있었다.

### 전/후 실측

같은 계획(임상 모듈 3개), 생성기 스텁으로 호출만 셈.

| | 전 | 후 |
|---|---|---|
| clinical_intro | generated | generated |
| clinical_result | **skipped** | generated |
| clinical_result_2 | **skipped** | generated |
| 생성기 호출 | 1회 | 3회 |

상한(`max_images=6`)은 그대로 걸린다. 게이트를 없앤 대신 상한 테스트를 추가했다.

**데모 골든셋이 정확히 이 케이스다**(실증자료 2건). 방치하면 시연에서 그대로 보였다.

## 4. 골든 입력 실행 결과

`docs/result/2026-08-23_시연용_골든입력.md`의 입력값 그대로, 이미지 끔.

```
카드 12장 · 재검증 위반 0 · 검토필요 3

[clinical_intro ] clinical_evidence  section_statement      ← stat: 다크스팟 개선=87%
[clinical_result] clinical_evidence  clinical_bar_compare   ← stat: 피부결 개선=2.1배
```

실증자료 카드 2장에 서로 다른 값이 실렸다. 계획기가 실제로 `clinical_bar_compare`를
골랐는데, 이제 그 카드도 `clinical_stat`을 들고 있어서 프론트가 그릴 수 있다.

이미지를 켜고 한 번 더 돌렸다(과금 실행 1회, 이미지 6장).

```
카드 11장 · 재검증 위반 0 · 검토필요 5

[clinical_intro ] clinical_evidence  img=generated  ← stat: 다크스팟 개선=87%
[clinical_result] clinical_evidence  img=generated  ← stat: 피부결 개선=2.1배
```

**임상 두 장 다 이미지가 붙었다.** 고치기 전이면 `clinical_result`가 `img=skipped`로
남았을 자리다. 상한 6장 안에 둘 다 들어갔다.

> 카드 수와 검토필요 수는 실행마다 흔들린다(`barum-vlm-run-variance`). 8/23엔 10장,
> 이번엔 12장(이미지 끔)·11장(이미지 켬)이었다. 자료 입력은 셋 다 같다.
> **위반 0은 세 번 다 같았다.** 검토필요 3→5 차이는 카드가 늘어 문장이 늘어난 것이고,
> 한 자릿수 차이로 개선·악화를 말하지 않는다.

## 5. 리뷰에서 걸린 것: 구조화 필드가 PII 마스킹을 우회했다

PM이 잡았다. `_strip_pii`가 `Section.text`만 `remove_pii()`에 태우고
`model_copy(update={"text": text})`로 돌려줘서, **`clinical_stat`은 마스킹을 전혀
안 거친 원본이 그대로 카드까지 흘렀다.**

`note`("피험자 수·조건 등 부연")·`institution`은 자유입력이다. 사업자가
`"20명 대상, 문의 02-1234-5678"`처럼 적으면 그대로 API 응답에 실린다.

### 확인해보니 하나가 더 있었다

`table_rows`도 같은 경로였다. 전성분·스펙표 섹션은 `text=""`이고 값이 전부
`TableRow`에 들어 있어서, `_strip_pii`가 빈 문자열만 훑고 지나갔다. 이건 #345가
아니라 **2026-08-23(#343)부터 있던 구멍**이다.

### 왜 필드를 나열해 막지 않았나

`_strip_pii`에는 원래 이런 주석이 있었다.

> 필드를 하나씩 나열해 재조립하면 새 필드가 추가될 때마다 여기서 조용히 유실된다.
> 실제로 `module_kind`가 그렇게 떨어져 나갔다(2026-08-20).

그 교훈으로 `text`만 갈아끼우게 바꿨는데, **정반대 방향의 구멍이 생겼다.** 필드가
유실되진 않지만 새 필드가 마스킹을 그냥 통과한다. 여기서 또 `note`·`institution`·
`table_rows`를 나열하면 다음에 필드가 늘 때 같은 일이 반복된다.

그래서 구조를 타고 내려가며 문자열이면 전부 훑는다(`_mask_pii_deep`). 중첩 모델도,
모델의 목록도 따라간다. `kind`·`source` 같은 내부 고정값도 지나가지만 PII
패턴(이메일·주민번호·전화번호)에 걸릴 수 없어 안 바뀐다.

```
제거된 종류: ['이메일', '전화번호']
text      : 문의 [개인정보 제거됨] 로 연락
stat.note : 피험자 20명, 문의 [개인정보 제거됨]
stat.claim: 다크스팟 개선 | value: 87%        ← 수치는 그대로
rows      : [('', '나이아신아마이드'), ('문의', '[개인정보 제거됨]')]
원본 안 바뀜: 피험자 20명, 문의 lab@yourlab.co.kr
```

`pytest 793 통과`(PII 테스트 5개 추가).

## 6. 통합 실행에서 또 걸린 것: 이미지 상한을 자유생성 카피가 먼저 먹는다

오늘 여섯 개 PR(#342~#347)이 전부 같은 생성 경로에 들어갔다. 각각은 자기 시점에
초록이었지만 **합쳐진 main에서 데모를 통째로 돌려본 적이 없어서** 한 번 돌렸다.
거기서 나왔다.

`generate_module_images`가 **계획 순서대로** 돌면서 6장을 채우고 끝냈다. 자유생성
카피 모듈이 앞에 몰리면 사업자가 낸 실증자료 카드가 이미지를 못 받는다.

같은 골든 입력으로 세 번 돌린 결과다.

| | clinical_intro | clinical_result |
|---|---|---|
| 실행 A | 이미지 있음 | 이미지 있음 |
| 실행 B | **상한으로 스킵** | 이미지 있음 |
| 실행 C | **상한으로 스킵** | **상한으로 스킵** |

실행 C에서는 `bundle_suggestion`(번들 추천) 카피 카드가 6번째 자리를 먹고 임상 두 장이
다 밀렸다. **실행마다 달라져서 리허설에선 멀쩡하다가 본 발표에서 터지는 유형이다.**

### 카드 상한에서 이미 겪은 문제였다

같은 날 오전에 `CARD_LIMIT`을 고쳤다. 팀장 지시가 "실증자료까지 너희가 다 넣어"였고,
보호 모듈이 자유생성 카피에 밀리지 않게 카드 상한을 갈랐다. **그때 이미지 상한엔 같은
수정을 안 넣었다.** 그래서 카드는 남는데 그 카드의 이미지만 사라지는 상태가 됐다.

### 무엇을 바꿨나

상한을 나눠줄 **순서**만 바꿨다. 상한 자체(6장)는 그대로다.

```
0) 첫 모듈(히어로)      맨 위 큰 자리가 비면 제일 티가 난다
1) 사업자가 낸 자료      실증자료·설문. 넣었는데 안 실리면 안 된다
2) 나머지 자유생성 카피
```

**프롬프트 내용은 안 바뀐다.** `build_image_prompt`가 계획 위치를 안 쓰기 때문이다
(쓰는 건 `variation_index`뿐인데 그건 같은 layout_type이 몇 번째로 *생성*됐는지라
원래도 계획 위치와 별개다). 검토 단계에서 "톤 교차 리듬이 흔들리는 건 감수한다"는
합의가 있었는데, 확인해보니 그 대가를 실제로는 안 내도 됐다.

결과 목록은 계획 순서로 되돌린다. 카드 짝짓기는 `kind`로 하니 무관하지만, 로그를
사람이 읽을 때 화면 순서와 같아야 헷갈리지 않는다.

### 전/후 실측 (골든 입력, 이미지 생성기 스텁이라 과금 없음)

```
전: [texture_visual] generated   [how_to_use] generated   [bundle_suggestion] generated
    [clinical_intro] 상한 스킵   [clinical_result] 상한 스킵

후: [clinical_intro] generated   [clinical_result] generated   [survey_result] generated
    [texture_visual] 상한 스킵   [how_to_use] 상한 스킵   [bundle_suggestion] 상한 스킵
```

**생성 장수는 전후 모두 6장이다.** 누가 가져가는지만 바뀌었다.

`pytest 801 통과`. 새 테스트 5개 중 2개는 **수정 전 코드에서 실제로 실패하는 걸
확인했다**(통과하는 테스트를 보고 고쳤다고 착각하지 않으려고).

## 7. 남은 것

- **진짜 before/after 막대비교는 여전히 불가능하다.** 입력에 기준값이 없다. (나)안을
  하기로 하면 인터뷰 폼·`ClinicalEvidence`·프론트를 같이 손봐야 한다.
- `clinical_photo_compare`도 같은 이유로 못 채운다. 전/후 사진을 구분해 받지 않는다.
