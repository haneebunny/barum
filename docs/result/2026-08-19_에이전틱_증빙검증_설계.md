# 에이전틱 증빙 검증 설계 (에스코 위조 사례 대응)

> 담당: 도도. 팀장 지시(2026-08-19)로 착수. **1단계(대상 선별) 구현 완료, 2단계(이미지 대조)는 설계까지.**
> 배경 사건: `docs/result/2026-08-15_확장정답셋_인용검증_보고서.md` §2.
> 이 문서는 구현 전 합의가 필요한 결정 3건(§4)을 담는다. 그 답이 나와야 2단계를 짤 수 있다.

---

## 1. 무엇을 푸는가

에스코 상품 광고에 "미백 주름개선 2중 기능성을 **보고한** 제품입니다"라는 문구와 함께
"결과확인서" 이미지가 붙어 있었다. 그 확인서는 **완전히 다른 제품**("에스코 로즈 PDRN 앰플크림")의
**피부 일차자극 패치테스트** 결과지였다. 제품명도, 시험 항목도 광고 중인 세럼과 무관했다.

독립된 두 LLM이 텍스트만 보고 **둘 다 못 잡았다.** 한쪽(luna)은 "근거 이미지가 제시됨"을 이유로
**합법으로 판정**했다. 같은 위조 문서가 다른 상품(49번)에도 재사용됐는데, 그쪽은 두 모델이 우연히
일치해 자동확정으로 넘어갔다.

**핵심**: 문서가 **존재한다**는 것과 그 문서가 **해당 제품·해당 주장과 일치한다**는 것은 별개다.
모델을 늘려도 이 구분은 안 생긴다. 원본 대조라는 다른 능력이 필요하다.

## 2. 구현 가능성 확인 (코드 확인 완료)

| 필요한 것 | 현재 상태 |
|---|---|
| 원본 이미지 바이트 | `pipeline.run_check`가 갖고 있다 (`image_bytes`) |
| 제품명 | `run_check(product_name=...)` 이미 있다 |
| 문장이 이미지 어디서 왔는지 | `Finding.location`에 `tile`·`y_start`·`y_end`·`source_h/w` 있다 |
| 판정기에서 이미지 접근 | **없다.** `judge.judge()`는 문장 dict만 받는다 |

→ 그래서 **판정기 안이 아니라 `run_check`의 판정 후 단계로 붙인다.** 판정기 인터페이스를 안 건드리고,
`StubJudge`·`PromptJudge`·`RagJudge` 어디를 쓰든 동일하게 동작한다.

## 3. 설계

```
run_check
  ├ OCR → 문장
  ├ 상품 대상외 게이트
  ├ judge.judge()  → findings
  └ [신설] 증빙 검증 단계
        ├ 1단계 select_for_verification(문장)   ← 순수 로직, 비용 0  ✅ 구현됨
        └ 2단계 이미지 대조 (VLM 이미지 호출)     ← 설계만
```

### 1단계 — 대상 선별 (구현 완료)
`reference/evidence_claim.py`. 증빙 표지(인증·시험·심사·보고·확인서·등록·임상·검사·특허·결과지·성적서)가
있고 **이미지에서 온** 문장만 고른다. 텍스트 입력은 대조할 원본이 없으니 제외한다.

키워드 축은 비비가 자동확정 705건을 16건으로 좁힐 때 쓴 것을 그대로 코드화했다. 즉 **사람이 실제로
써서 위조를 찾아낸 필터**다.

"피부과 테스트 완료"류는 **일부러 제외**했다. La Nieve 사례처럼 배지 텍스트만 있고 첨부 문서가 없는
경우라 대조할 대상이 없다(그건 이미 `judge_rules.json`의 `테스트완료` 규칙이 검토필요로 잡는다).

### 2단계 — 이미지 대조 (설계)
선별된 문장마다 원본 이미지를 VLM에 다시 보내고 **좁은 질문**을 한다.

- 이 이미지에 첨부된 증빙 문서에 적힌 **제품명**이 광고 중인 제품(`product_name`)과 같은가?
- 그 문서의 **시험·심사 항목**이 문장이 주장하는 효능(미백·주름개선 등)과 같은가?
- 애초에 **첨부 문서가 있기는 한가?**

판정 반영은 **한 방향으로만** 한다.

| 대조 결과 | 조치 |
|---|---|
| 제품명 불일치 **또는** 시험항목 불일치 | **위반으로 격상** (별표5 사목: 사실과 다르거나 부분적 사실이라도 전체적 오인·기만) |
| 일치 | 기존 판정 유지 (합법으로 안 내린다, §4-C 참고) |
| 첨부 문서 없음 | 기존 판정 유지 |
| 판독 실패·저신뢰 | 기존 판정 유지 |

**격상만 하고 강등은 안 한다.** 이유는 두 가지다. 강등하면 이 단계가 새 미탐 경로가 된다. 그리고
Anna Holtz 사례처럼 증빙이 진짜여도 "성분 언급 자체가 §4① 검토필요"인 건 그대로라, 문서 진위와
합법 여부가 1:1이 아니다.

## 4. 합의가 필요한 결정 (구현 전)

### A. 비용을 어디까지 허용하나
이미지 VLM 호출은 텍스트보다 비싸다. 지금 설계는 "증빙 표지 문장이 하나라도 있으면 이미지 1회 호출"이다.
정답셋 53상품 기준으로 비비가 추린 게 9개 상품(16문장)이었으니 **대략 5~6개 상품 중 1개꼴**로 추가
호출이 붙는다. 이 빈도를 받아들일지, 아니면 더 좁힐지(예: 2호 기능성 주장에만) 정해야 한다.

### B. 제품명이 없을 때
`product_name`은 선택 입력이다. 없으면 "문서의 제품명 vs 광고 제품명" 대조를 못 한다. 두 갈래:
- (B1) 제품명 없으면 **시험항목 일치만** 본다(에스코는 시험항목도 불일치라 이것만으로도 잡혔다).
- (B2) 제품명 없으면 이 단계를 **아예 건너뛴다**(오판 위험 회피, 대신 탐지 못 함).

지금은 **B1을 권한다.** 에스코 케이스가 실제로 시험항목만으로도 걸린다.

### C. 증빙이 진짜로 확인되면 합법으로 내려도 되나
지금 설계는 "안 내린다"이다. 다만 사용자 입장에선 "확인서까지 붙였는데 왜 계속 검토필요냐"가 나올 수
있다. `type_2_functional_misperception.md`는 **심사보고서 발췌가 지면에 있고 문구가 인정문구와 일치하면
합법 확정 가능**이라고 이미 적고 있어서, 규정상으로는 강등 근거가 있다. **다만 이건 판정 정책 변경이라
따로 승인이 필요하다고 본다.** 이번 범위에서는 격상만 한다.

## 5. 이번에 한 것 / 안 한 것

**했다**: 1단계 순수 로직 + 테스트 6건. 비용 0, 판정 동작 변경 없음(아직 아무 데서도 호출 안 함).

**안 했다**: 2단계 이미지 대조 구현. 이유가 둘이다.
1. §4의 결정 3건이 먼저 필요하다.
2. **`.env` 유실로 VLM 실호출이 불가능한 상태다**(2026-08-19, 내 실수. 키 복구 대기 중). 이미지
   대조는 실제로 돌려서 에스코 원본으로 검증하지 않으면 의미가 없다.

**검증 계획**(키 복구 후): 에스코 48·49번 원본 이미지로 위조를 실제로 잡는지, 그리고 Anna Holtz
특허증·HERA 표처럼 **진짜인 케이스를 위반으로 오판하지 않는지** 양쪽을 확인한다. 한쪽만 보면 안 된다.
