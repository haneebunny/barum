# 이미지에 박힌 문구를 AI로 고칠 수 있나 (2026-08-23)

> 담당: 백엔드6. 결론: **지금은 못 쓴다. 접었다.**
> 재현: 원본 `backend/11st_probe_cosmetic/read_test/images/11_8783520869_detail_006.png`

## 왜 해봤나

상세페이지는 문구가 이미지에 그래픽으로 박혀 있는 경우가 많다. 그런 문구는 **텍스트를
고쳐도 화면에는 위반 표현이 그대로 남는다.** 나노 바나나가 참조 사진의 라벨을 잘
보존한다는 실측(2026-08-20)이 있어, 이미지째 넘겨 문구만 바꿔달라고 해봤다.

대상은 `약국 입점 화장품` 배지가 박힌 실제 크롤 이미지다.

## 결과

| | 시도 ① 전체 이미지 편집 | 시도 ② 위반 영역만 크롭 편집 |
|---|---|---|
| 지정 문구 교체 | 됨 | **한글 틀림** (`데일리 리페어` → `데일리 화장어`) |
| 영어 문구 교체 | — | 됨 (`Daily-repair`) |
| 제품 라벨 | **깨짐** (`REJULAB REPAIR CREAM` → `RREJ LAR EEPAIR CEAM`) | 해당 없음 |
| 성분 표기 | **좌우 반전** (`PDRN 3,000PPM`) | 해당 없음 |
| 하단 성분표 | **오타 발생** (`콜라겐수`→`클라겐수`, `판테놀`→`판테늘`) | 해당 없음 |
| 크기 | 900×2062 → 672×1540 | 200×210 → 1008×1058 (5배 확대 반환) |
| 소요 | 9.3초 | 9.0초 |

## 왜 안 되나

**보존과 생성은 다른 능력이다.** 2026-08-20에 확인한 건 "참조 사진의 라벨을 지키는"
능력이고, 이번에 필요한 건 "지정한 한글로 정확히 바꾸는" 능력이다. 앞쪽은 되고
뒤쪽은 안 된다. 영어는 맞고 한글만 틀린 것도 같은 결이다.

## 접은 진짜 이유 — 실패 방향이 나쁘다

성분표 오타가 결정적이다. **전성분 표시는 화장품법상 의무사항**이라, 위반 하나를
고치려다 **전성분 표기 오류라는 새 위반을 만든다.** 컴플라이언스 도구에서
무행동은 오작동보다 낫다.

## 대안 (로드맵)

**이미지를 다시 그리지 말고 덮어쓴다.** `Finding.location`에 OCR bbox 좌표가 이미 있다.

1. bbox로 위반 문구 영역을 잡고
2. 그 영역을 지운 뒤
3. 대체표현을 **우리가 폰트로 렌더**한다(상세페이지 폰트 3단은 확정돼 있음)

| | AI 편집 | 덮어쓰기 |
|---|---|---|
| 텍스트 정확도 | 한글 오타 | **정확**(우리가 그림) |
| 나머지 영역 | 재생성돼 깨짐 | **비트 단위 동일** |
| 비용 | 과금 + 9초 | **0원, 즉시** |
| 남는 문제 | 새 위반 생성 | 배경이 복잡하면 자국이 보임 |

배경 복원이 필요한 자리에만 나노 바나나를 쓰면 된다. 그건 생성이 아니라 **인페인팅
(보존·복원)**이라 이 모델이 잘하는 쪽이다.
