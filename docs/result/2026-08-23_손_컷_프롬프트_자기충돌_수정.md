# create 모드 손 장면이 안 나오던 이유 — 프롬프트 자기충돌 (2026-08-23)

> 담당: 버그담당(그그). 결론: **배관 버그 아님, 프롬프트 자기충돌. 수정 후 실제 생성으로 확인.**
> #312(라벨 버그)와 같은 계열의 결함. 코드: `backend/src/barum/generate/images.py`

## 왜 봤나

팀장 지적: 오늘 나온 실제 상세페이지 이미지 4장이 전부 "제품 무드샷"·"텍스처 클로즈업"이고
손등·얼굴 적용 컷이 하나도 없었다. PM 지시로 "layout_type이 실제 최종 프롬프트까지
도달하는지"를 LangSmith 실 트레이스로 확인.

## 확인된 것 — 배관은 정상

`barum` LangSmith 프로젝트의 `nano-banana.image` 트레이스를 직접 열어 확인(코드 읽고 추론
안 함). 실제 상품("리쥬랩 리페어 크림") 생성에서 `step_list`(사용법 안내) 모듈의 프롬프트에
`_HAND_ALLOWED_LINE`이 정확히 들어가 있었고, `image_text_split`(성분 소개) 등 손 금지
유형엔 안 들어갔다 — `_HAND_ALLOWED_LAYOUT_TYPES`(images.py) 설계 그대로.

## 진짜 원인 — "들어갔다"와 "이겼다"는 다르다

같은 프롬프트 "절대 넣지 말 것" 섹션에 layout_type과 무관하게 항상 이 문구가 있었다:

```
- 실제 사용 후기·체험담처럼 보이는 연출을 만들지 마라(사용 전후 비교, 손으로
  직접 촬영한 듯한 스냅샷 구도 등). 얼굴이 없어도 금지다. 실제 후기로 오인되면
  안 된다.
```

`step_list` 모듈의 실제 프롬프트 안에 "손 장면 넣어도 된다"(약한 허용, "필요하면")와
이 문구(강한 금지, 볼드+"얼굴이 없어도 금지다"로 손 장면 예외를 명시적으로 다시 막음)가
**같이** 들어 있었다. #312(라벨 버그: "라벨 유지하라" vs "글자 전부 금지", 볼드+"최우선"
반복 쪽이 이김)와 정확히 같은 패턴 — 더 강하게 쓰인 금지가 이겨서 손 장면이 억제된 것으로
추정.

## 수정

`_body_part_line`과 같은 기준(`_HAND_ALLOWED_LAYOUT_TYPES`)으로 금지 문구도 갈랐다.
손이 금지된 유형은 원문 그대로, 손이 허용된 유형(`hero_fullbleed`·`step_list`)만 "허용한
손 장면은 예외"라고 명시하는 문구로 교체:

```
- 일반 소비자가 스마트폰으로 찍은 듯한 캐주얼한 셀피·인증샷 구도는 만들지 마라
  (흔들린 각도, 어수선한 배경, 사용 전후 비교 등 실제 후기로 오인될 연출). 위에서
  허용한 손 동작 장면은 이 금지 대상이 아니다 - 브랜드 화보처럼 정돈되고 의도적인
  구도라면 손이 나와도 된다.
```

원래 문구의 의도(진짜 사용자 후기로 오인되면 안 됨)는 유지하면서, 의도적으로 열어준
손 장면과의 충돌만 없앴다.

## 검증 — 실제 생성 1회 (전/후 비교)

**전**: 오늘 실제 배포에서 나온 4장(팀장 확인) — 무드샷·텍스처 클로즈업만, 손 장면 0장.
LangSmith 트레이스로 프롬프트 자체엔 허용 문구가 있었음을 재확인(위 인용).

**후**: 같은 조건(크림, `step_list`, "사용법 단계별 안내") 재구성해 실제로 1회 생성.

## 안 건드린 것

**"얼굴에 바르는 컷"은 그대로 둠.** `_PROMPT`의 "사람 얼굴은 어떤 형태로도 넣지 마라"는
layout_type과 무관한 하드 규칙이고, 오늘 발견한 자기충돌 패턴과 무관하게 **처음부터 예외가
없다.** 이건 프롬프트 버그가 아니라 정책 결정(안전규칙을 풀지 말지) 사안이라 임의로 안 바꿈
— 팀장·PM 확인 대기.
