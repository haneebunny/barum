# 프롬프트 전후 기록 (2026-08-23)

> 담당: 백엔드6. 팀장 지시로 오늘 고친 프롬프트의 **실제 전후 원문**을 남긴다.
> 지어낸 값이 아니다. before는 수정 전 커밋에서 그대로 꺼냈고(`git show <sha>^`),
> after는 현재 main 코드다. 이미지 프롬프트의 after는 LangSmith 트레이스로도 확인했다.
>
> **출처 주의**: before를 LangSmith 트레이스로 캡처하진 못했다. Gemini 계측을 오늘
> 오후에야 붙였고(PR #309) 그 시점엔 이미 아래 수정이 머지된 뒤였다. 그래서 before는
> "그 시점 코드가 실제로 만들던 문자열"이지 "그때 실제로 전송된 트레이스"는 아니다.

## 1. 모듈 카피 프롬프트 — 헤드라인 구분자 (PR #311, `c242fc6`)

### 증상
카드 6장 중 4장의 헤드라인이 30자 넘는 문장이 되고 본문이 잘렸다. 히어로는 본문이 비었다.

### 원인
"첫 문장은 20자 이내"만 요구하고 **구분자를 안 정했다.** 모델이 줄을 안 바꾸고 이어 쓰면
`split_headline`이 첫 마침표까지 삼킨다.

### Before
```
**문장 구조를 반드시 지켜라. 프론트가 첫 문장을 헤드라인으로 크게 키워 쓴다.**
- **첫 문장은 20자 이내의 짧은 한 마디**여야 한다. 설명하지 말고 던져라.
  좋은 예: "속기미, 왜 생길까요?" / "발림성부터 다릅니다" / "이렇게 쓰세요"
  나쁜 예: "칙칙함이나 속기미는 수면, 스트레스, 외부 환경 등 여러 요인으로 인해
  피부 표면에서 나타나는 현상일 수 있습니다." (설명을 첫 문장에 넣었다)
- 설명은 **두 번째 문장부터** 2~3문장으로 쓴다.
- 첫 문장이 길면 상세페이지에서 큰 글씨가 다섯 줄로 흘러 헤드라인 구실을 못 한다.
```

### After
```
**형식을 반드시 지켜라. 프론트가 첫 줄을 헤드라인으로 크게 키워 쓴다.**
- **헤드라인을 첫 줄에만 쓰고, 줄을 바꾼 뒤 설명을 이어라.** 이게 제일 중요하다.
  text 값 안에 줄바꿈 문자(\\n)를 넣으라는 뜻이다.
- **헤드라인은 20자 이내의 짧은 한 마디**다. 설명하지 말고 던져라.
- 설명은 둘째 줄부터 2~3문장으로 쓴다.

  올바른 예: "발림성부터 다릅니다\\n젤-세럼 타입의 가벼운 제형입니다. 끈적임이 거의 없습니다."
  틀린 예:   "발림성부터 다릅니다 젤-세럼 타입의 가벼운 제형입니다. 끈적임이 거의 없습니다."
             (줄을 안 바꿔서 헤드라인이 어디서 끝나는지 알 수 없다)
- 줄을 안 바꾸면 큰 글씨가 여러 줄로 흘러 헤드라인 구실을 못 한다.
```

### 실측
```
전: 카드 6장 중 4장 헤드라인이 문장 (예: "성분의 조화 히알루론산 계열의 수분감을 주는 성분과 가벼운 오")
후: 6/6 정상, 헤드라인 7~13자
```

## 2. 모듈 카피 프롬프트 — create 모드 전성분 (PR #311, `c242fc6`)

### 증상
사업자가 성분을 입력했는데 LLM이 "전성분 표기는 제공되지 않습니다"라는 사과문을 썼다.

### 원인
create 모드는 `ingredients`가 아니라 `ingredient_amounts`에 성분을 담는데(전자는 improve
모드 입력), 카피 프롬프트는 `ingredients`만 봤다.

### Before / After
```python
ingredients=req.ingredients or "(미상)",
ingredients=_ingredients_for_prompt(req),
```

### 프롬프트에 실제로 들어간 값
```
전: 전성분: (미상)
후: 전성분: 나이아신아마이드 3%, 히알루론산 1%
```

### 실측
```
전: "전성분 안내  현재 전성분 표기는 제공되지 않습니다. 구매 전 상품 라벨에서 …"
후: "나이아신아마이드와 히알루론산을 중심으로 가볍게 구성된 포뮬러입니다."
```

## 3. 이미지 프롬프트 — 글자 규칙 자기모순 (PR #312, `d62913e`)

### 증상
판매자가 제품사진을 올렸는데 **라벨이 하나도 없는 빈 병**이 생성됐다.

### 원인
프롬프트가 자기 자신과 충돌했다. 참조 사진이 붙을 때만 켜지는 합성 지시는
`"참조 사진 속 병·용기의 형태·라벨·색상을 그대로 유지하라"`인데, 최상단 규칙은
`"인쇄된 라벨 전부 포함"` 금지였다. **"최우선"이라고 두 번 강조된 쪽이 이겼다.**

배관은 멀쩡했다. LangSmith 트레이스로 참조 이미지가 실제로 도착한 것을 확인했다.
```
name: nano-banana.image
inputs: {'images': ['<image 1,540,781 bytes>'], 'prompt': '화장품 상세페이지에 쓸 **배경 이미지**를 …'}
```

### Before (참조 사진 유무와 무관하게 항상 이 규칙)
```
# 최우선 규칙: 이 이미지에는 글자가 단 하나도 없어야 한다
읽을 수 있는 문자를 어떤 형태로도 그리지 마라. 한글·영문·숫자·로고·워터마크·
인쇄된 라벨 전부 포함이다. 글자처럼 보이는 장식적 흘림선도 안 된다.
아래에 제품명이 적혀 있지만 그건 **무엇을 그릴지 알려주는 정보일 뿐, 화면에
쓰라는 뜻이 아니다.** 제품명·브랜드명을 이미지 안에 절대 쓰지 마라.
완성된 이미지는 **글자가 하나도 없는 순수한 사진**이어야 한다.
```

### After (참조 사진이 있을 때만 이 규칙으로 갈린다)
```
_KEEP_LABEL_TEXT_RULE = """# 최우선 규칙: 용기에 인쇄된 라벨만 남기고, 나머지 글자는 전부 없앤다
글자를 세 갈래로 구분하라.

1. **남길 것 — 참조 사진 속 제품 용기 표면에 인쇄된 것**
   브랜드명·제품명·용량 표기처럼 병·튜브·패키지에 직접 찍힌 글자다. 실제 제품의
   일부이므로 그대로 두어라. 지우거나 뭉개거나 철자를 바꾸지 마라.

2. **옮겨 그리지 말 것 — 참조 사진의 배경에 얹혀 있는 글자**
   광고 문구·제목·설명 문장·성분표·배지·워터마크가 여기 해당한다. 참조 사진에
   있더라도 **새 이미지에는 넣지 마라.** 그건 제품이 아니라 남의 페이지 디자인이다.

3. **새로 만들지 말 것 — 그 외 모든 글자**
   한글·영문·숫자·로고를 배경·연출에 새로 그리지 마라. 글자처럼 보이는 장식적
   흘림선도 안 된다.

아래 제품명은 **무엇을 그릴지 알려주는 정보일 뿐**이다. 화면에 쓰라는 뜻이 아니다.
결과는 **용기의 라벨 외에는 글자가 없는 사진**이어야 한다.
```

참조 사진이 없을 때는 Before 규칙을 그대로 쓴다. 모델이 그리는 라벨은 뭉개진 가짜
글자가 되기 때문이다(39b2b54).

### 두 갈래로는 안 됐다 (중간 실패 기록)
처음엔 "남길 것 / 새로 만들 것" 두 갈래로 고쳤다. 로고는 살았지만 **참조 페이지의
광고 문구·제목·성분표를 통째로 복제**했다. 모델 입장에선 그것도 "새로 쓴 글자"가
아니라서다. 기준은 *새것이냐*가 아니라 **글자가 어디에 있느냐**여야 했다.

### 실측
```
전: 빈 병 (브랜드 글자 없음)
1차 수정 후: 로고는 살았으나 원본 페이지 카피를 통째로 복제
최종: REJULAB 로고 · 세로 라벨 "REJULAB REPAIR CREAM" · 50ML 표기 유지,
      원본 페이지 카피는 사라지고 크림 텍스처 배경으로 연출
```

## 남는 한계

- 프롬프트 준수는 확률적이다. 위 실측은 각 1~2회 실행이라 **"해결"을 단정하지 않는다.**
  다만 구분자를 안 정한 것과 규칙이 서로 모순된 것은 **구조적 결함**이고 그건 닫혔다.
- 용기의 아주 작은 성분 미세표기는 여전히 뭉개진다. 실제 상세페이지 크기에선 판독
  불가한 글씨라 이번 범위에 넣지 않았다.
