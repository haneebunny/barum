# 기술 선택 분석: 비용 논리 + 성능 비교 (2026-08-08)

> 주제: 우리 DL 코어(선생-학생 지식증류)를 유지할지, LLM-first로 갈지.
> 배경: 신재웅 멘토 "성능 비교할 것도 없이 LLM 승." 하니 "비용 때문에 DL을 잡았고, 성능 비교를 해보려 했다."
> 성격: 분석 + 권고. 확정 결정 아님. 관련: `멘토링_피드백_정리.md`, `PROJECT.md` §2·§3.
> 전제: 최종프로젝트 평가에 "자체 DL 학습" 요건은 없음(하니 확인, 2026-08-08).

---

## 0. 결론 요약

- 이 케이스에선 멘토 말이 대체로 맞다. **LLM-first가 맞다.**
- 단 "비교할 것도 없다"에는 반만 동의한다. 비교는 이기려고가 아니라 **의사결정을 데이터로 증명하는 포트폴리오 증거**라서, 가볍게 타임박스로 해두는 게 좋다.
- **재학습(F18 '학습시키기')은 살린다.** 우리 "닫힌 순환" 정체성(`PROJECT.md` §1: 탐지→검토→조치→추적→재학습)의 일부이고, 핵심은 아니어도 빠지기 아까운 차별화 포인트다. LLM-first로 가면 이게 사라지는 게 아니라 **두 층으로 갈라지며 더 선명해진다**(§3-2).
- DL을 완전히 죽이지는 마라. **재학습 루프 + 온프렘 배포 카드 + 증류 내러티브**로 남긴다.
- ② 이미지유형 CNN은 명분이 사라졌으니 제거한다. (스코프 축소)

한 줄: **주력 프로덕트 = LLM+RAG+온톨로지. DL = 재학습 루프 + 얇은 비교/증거 트랙 + 온프렘 카드. 블로킹은 걸지 않는다.**

## 1. 비용 논리: DL의 비용우위는 착시

DL을 잡은 이유가 비용이었다. 그런데 그 근거가 약하다.

- **`PROJECT.md` §2-4의 "학습 컴퓨트 ~$0(Colab T4)"는 학습 비용만 센 것이다.** 진짜 비용인 라벨링 + OCR + 엔지니어 시간 + 재학습 운영이 빠졌다.
- **라벨링 비용은 어느 쪽으로 가도 똑같이 든다.** DL이든 LLM이든 정답셋은 필요하다. 여기서 DL이 아끼는 게 없다.
- **LLM 추론 비용은 실제로 싸다.** flash급이면 문장 하나 판정에 컨텍스트(조항 + 주변문맥)를 다 넣어도 2~3K 토큰. 우리 전체 데이터가 수백~수천 문장 규모다.
  - 개략 추산: 문장 1만 건 × 3K 토큰 = 약 30M 입력토큰. flash 단가 기준 한 자릿수 달러. 월 재실행해도 만 원 안쪽.
  - 멘토의 "한 달에 만원도 안 나온다"와 일치한다.
- **결론: 코랩 충전 2회를 아끼려고 DL을 붙드는 건, 더 큰 비용(시간·복잡도)을 지불하는 것이다.** 비용은 DL 편이 아니다. 오히려 반대다.

## 2. 성능 비교: LLM이 이길 것이다, 근데 이유가 우리 데이터에 있다

멘토는 "트렌드라서"라고 했지만, 우리 데이터를 보면 더 구체적인 이유가 있다.

### 2-1. 왜 LLM이 유리한가 (근거 3개)

- **학습 데이터가 적다.** goldset 215 + holdout 331 = 약 546문장을 7개 클래스로 쪼갠다. KoELECTRA 파인튜닝엔 빈약하다.
- **클래스 불균형이 치명적이다.** 2호(의약품오인)가 goldset·holdout 각각 2문장이다(`ROADMAP.md` §3). 2개짜리 클래스는 지도학습으로 못 배운다. 반면 LLM은 프롬프트에 "2호 = 의약품 오인" 정의만 넣으면 예시 0~2개로도 판정한다. rare 클래스에서 LLM이 압도한다.
- **우리 정책이 recall 우선이다(`PROJECT.md` §2-5).** 미탐 잡는 게 핵심인데, 소량학습 분류기는 안 배운 유형을 통째로 놓친다. LLM + 조항 컨텍스트가 유리하고, 미탐 회수 캐스케이드(다른 모델 재판정 F19/F15)와도 잘 붙는다.

| 조건 | 소량 파인튜닝 DL | LLM + RAG |
|---|---|---|
| 학습 데이터 546문장 | 빈약, 과적합 위험 | 예시 few-shot으로 충분 |
| 2호 2문장 | 사실상 학습 불가 | 조항 정의로 판정 가능 |
| recall 우선 | 미학습 유형 미탐 | 조항 컨텍스트로 회수 유리 |
| 신규 위반유형 추가 | 재학습 필요 | 프롬프트/온톨로지 갱신 |

### 2-2. 그래도 비교는 하라 (멘토와 다른 지점)

- 멘토 "비교할 것도 없다"는 실무자 조언이다. 이길 게 뻔한 비교에 시간 쓰지 말라는 것. 맞다.
- **그러나 우리는 부트캠프 최종산출물이다. 비교 결과 자체가 포트폴리오의 핵심 증거다.**
  - "우리는 GPT 썼어요" 팀 vs "KoELECTRA 파인튜닝 vs LLM+RAG를 홀드아웃으로 실측했고, 소량데이터·클래스불균형 때문에 LLM이 미탐율에서 이겼다. 그래서 LLM-first로 결정했다"를 표로 보여주는 팀. 후자가 훨씬 강하다.
- **권고: 타임박스 가벼운 비교.** 며칠 잡고 홀드아웃에 양쪽 한 번씩 돌려 precision/recall/미탐율 표 한 장. 이기려고가 아니라 의사결정을 증명하려고. 무겁게 튜닝 반복하지는 않는다. 스코프 축소 원칙과도 안 부딪힌다.

## 3. DL을 완전히 죽이지 않는 이유

멘토는 "LLM 승"으로 끝냈지만, B(컴플라이언스 B2B) 방향에선 DL을 남기는 게 유리하다. 지금 주력은 아니고, 접지도 않는다.

### 3-1. 남기는 근거 (미래 카드)

- **온프렘 / 외부 API 미전송.** 기업 준법팀은 자사 광고물을 외부 LLM 서버로 보내는 걸 꺼릴 수 있다. 로컬에서 도는 증류 모델은 진짜 셀링포인트다. "LLM으로 라벨링해 경량 모델로 증류, 온프렘 배포 가능"은 B2B에서 먹히는 스토리.
- **결정론.** 규제 판정은 같은 입력에 같은 출력이 나와야 신뢰된다. LLM은 흔들린다. 분류기는 안정적이다. 법적 맥락에서 가치가 있다.
- **증류 내러티브가 원래 우리 기획의 강점.** "선생(LLM)-학생(DL)"은 그 자체로 인상적인 아키텍처다. 죽이면 아깝다.

### 3-2. 재학습(F18)은 두 층으로 살린다 (차별화 포인트)

재학습은 핵심 기능은 아니지만, "탐지하고 끝"이 아니라 **스스로 개선되는 닫힌 순환**이라는 차별화의 심장이다. LLM-first로 가도 사라지지 않는다. 오히려 두 층으로 갈라지며 선명해진다.

| 층 | 재학습의 의미 | 주기·비용 | 역할 |
|---|---|---|---|
| **LLM 층 (주력)** | 하네스가 오판 사례를 모아 **프롬프트/온톨로지를 갱신** | 상시·저비용 | 신재웅 멘토 "재학습 = 업데이트에 가깝다"의 그 지점. 빠른 개선 루프 |
| **DL 층 (차별화)** | 사람 승인 라벨이 일정량 쌓이면 **증류 학생모델 재학습** | 배치·저빈도 | 우리 원래 F18. 온프렘 카드에 실체를 준다. "모델이 실제로 학습한다" 증명 |

- 원래 F18은 `PROJECT.md` §2-2에서 "①만 재학습, 사람 승인 라벨만"이었다. 이 정의는 **DL 층에 그대로 유지**된다. 가드레일(자동 라벨 자기학습 금지)도 유지.
- LLM 층의 "가벼운 재학습"(프롬프트/온톨로지 갱신)이 새로 생긴다. 이게 상시로 돌고, DL 재학습은 라벨이 충분히 쌓였을 때 배치로 돈다.
- 발표 관점: "우리 시스템은 두 방식으로 스스로 개선된다. 실시간은 프롬프트·온톨로지 갱신, 주기적으로는 승인 라벨로 경량 모델 재학습." 한 층만 있는 팀보다 강한 스토리다.
- 주의: DL 재학습이 의미 있으려면 사람 승인 라벨이 최소 규모로 쌓여야 한다(현재 2호 2문장 같은 rare 클래스는 여전히 부족). 그래서 **LLM 층이 주력, DL 재학습은 데이터가 찰수록 강해지는 보조·차별화 트랙**으로 둔다.

## 4. ViT / ② 이미지유형 CNN: 제거

- ② CNN(인증서·후기·성분표·제품컷 분류)의 명분은 `PROJECT.md` §2-2에 "이미지 DL 요건 충족용"이라고 적혀 있었다. 요건이 아니라고 확정됐으니 유일한 명분이 사라졌다.
- 멘토 ViT/YOLO 발언이 이 지점이다. "이미지 유형이 뭔지"는 멀티모달 LLM에 태우면 부산물로 나온다. 전용 비전모델을 따로 학습할 이유가 없다.
- LLM-first 파이프라인에선 타일을 멀티모달 LLM에 주면 글자 읽기 + 이미지 유형 파악 + 위반 판정을 한 번에 한다. 라우터가 필요 없거나 공짜로 딸려온다.
- **② CNN은 로드맵(`ROADMAP.md` 5순위)에서 제거 검토.** 손실 없음.

## 5. 재정렬 후 파이프라인 (안, 확정 아님)

```
수집(11st/의약·화장품 소스) → 타일 분할 → 멀티모달 LLM 판정
  (OCR + 이미지유형 파악 + 위반유형 분류 한 번에)
  + RAG(법령 조항 청킹·매칭) + 온톨로지(OpenCrab) 컨텍스트
  → 계층 분류(대/중/소) → recall 우선 캐스케이드(다른 모델 재판정)
  → 사람 검수
  → [재학습 층 1] 하네스: 오판 사례로 프롬프트/온톨로지 갱신 (상시)

[재학습 층 2, 비블로킹] 증류 DL: 사람 승인 라벨 축적 → 경량 분류기 재학습 → 비교표/온프렘 카드
```

- 기존 자산(수집·타일·OCR·prescreen·레퍼런스·goldset/holdout·온톨로지)은 대부분 재활용.
- F18 '학습시키기'는 사라지지 않고 **두 층으로 갈라진다**(§3-2). 상시 갱신(프롬프트/온톨로지) + 배치 재학습(증류 DL). 원래 "①만 재학습, 사람 승인 라벨만" 정의는 DL 층에 유지.
