# 과대·부당광고 VLM 판정 — 예비 리포트 (Go/No-Go)

- 대상: 쿠팡 다이어트 보조제 **5개 상품 / 상세 45장** (2026-08-03 크롤링분, 디스크 기존 데이터)
- 방법: **라벨링 0장 · 학습 0회.** VLM(Claude)에 상세 이미지를 직접 입력 → OCR + 광고문구 추출 + 위반유형 분류 + 합법/위반 뉘앙스 판별
- 작성: 2026-08-04

---

## 1. 판정: **된다 (GO)** ✅

VLM이 한국어 상세페이지에서 **글자를 읽고 → 광고 문구를 뽑고 → 위반 유형을 분류하고 → 합법(승인 기능성)과 위반을 구분**하는 걸 학습 없이 즉시 수행함. 5개 상품 전부에서 판정 신호 확보.
→ "이미지 학습이 되냐"는 사실상 풀렸음. **CNN 이미지 분류기를 100~200장 라벨링해 학습하는 접근은 이 목표에 불필요/부적합.** 정공법은 VLM(+OCR 전처리).

## 3. 발견된 위반 유형 (→ 라벨 스키마 초안)

실제 데이터에서 관측된 유형. 이게 곧 판정 라벨 카테고리가 됨.

1. **질병 예방·치료 표현** — 비만/당뇨/고지혈증 등 질병명 + 예방·치료. (건기식 금지 1순위)
2. **소비자 후기 효과보증** — "살이 빠지기 시작", "붓기 빠짐" 등 체험 후기로 효과 단정.
3. **배타성·비교광고** — "일반 제품 vs 자사" X/O 비교표, "국내 최초".
4. **안전성 단정** — "부작용 없다", "안전한".
5. **최상급·절대표현 / 특허 남발** — "4개국 특허" 반복 강조 등.
6. **[합법 — 위반 아님으로 걸러야 함]** — 개별인정 원료의 승인된 기능성 문구(체지방 감소 등). ← **여기서 오탐 내면 시스템 신뢰도 붕괴.**

## 4. 기술적 발견 (파이프라인 필수 요구사항)

- **45장 중 14장이 세로비율 4배 이상**, 최대 **35.9배(780×27992px)**. 화면·모델 입력에 맞춰 축소하면 **글자가 뭉개져 판독 불가.**
- 상품 2개(가르시니아·BNR17)는 **핵심 정보가 초장문 1장에 통째로** 들어있어, 전처리 없이는 그 상품 판정 자체가 불가.
- → **상세 이미지 타일 분할(예: 세로 1200~1500px 단위 슬라이스) 전처리가 필수.** 없으면 미탐(놓침) 발생.
- 정보 밀도 편차 큼: 한 상품은 21장 분산, 다른 상품은 1장 집중.

## 5. 정확도의 진짜 관건 (다음 스텝)

- **식약처 승인 기능성 원료·문구 레퍼런스**를 VLM에 물려야 합법/위반 오판 방지 (예: 가르시니아 HCA·돌외잎·BNR17의 체지방감소는 합법).
- **판정 단위 = "이미지"가 아니라 "상품".** 한 상품이 여러 장/한 장에 흩어져 있으므로 상품 단위 집계 필요.

## 6. 권고

1. **이미지 학습 여부: GO 확정.** 남은 3주를 CNN 학습이 아니라 아래에 투입.
2. **(전처리)** 초장문 상세 이미지 타일 분할 스크립트.
3. **(레퍼런스)** 식약처 부당광고 기준 + 승인 기능성 원료 리스트 정리 → VLM 프롬프트에 주입.
4. **(검증)** 소량(20~30 상품) 정답 라벨로 정밀도/재현율 측정. ← 라벨링은 "학습용"이 아니라 "검증용"으로만.
5. **(데이터)** 11번가 크롤러 상세페이지 수집 수리(현재 썸네일만 수집 → 광고문구 없음). → **아래에서 해결됨.**

## 부록: 상세페이지 크롤 방식 결정 (실측)

**결론: 11번가로 물량 확보. 순수 requests로 상세 이미지 수집 가능 (브라우저 불필요).**

| 플랫폼 | 상품목록/URL | 상세 접근 | 상세 이미지 확보 | 안티봇 |
|---|---|---|---|---|
| **11번가** ✅채택 | 공식 Open API (자동) | HTTP 200 정적 | **`/products/{id}/view-desc` 순수 requests** | 약함 |
| 네이버 | 검색 API(키), 웹검색 차단 | 418/429/307 | smartstore API(봇차단 뚫어야) | 강함 |
| 쿠팡 | 없음 | 반수동 브라우저 | 확보됨(기존 45장) | 최강 |

**11번가 확정 파이프라인** (구현: `fetch_11st_desc.py`):
1. Open API → `prdNo` 목록 (완전 자동)
2. `GET https://www.11st.co.kr/products/{prdNo}/view-desc` (+Referer 헤더) → 상세 HTML 조각
3. `<img src>` 파싱 → 상세 마케팅 이미지 다운로드 (셀러 호스트 `gi.esmplus.com` 등)

- 발견 방법: Playwright로 상세 페이지 네트워크 로깅 → 상세설명이 `view-desc` iframe임을 확인 → 그 조각을 순수 requests로 직접 취득.
- 실측: 샘플 상품 상세 메인 이미지 **860×29,000px** (다이어트 커피 과대광고 통짜 이미지) → **타일 분할 전처리 필수 재확인.**
- 쿠팡(반수동 브라우저)·네이버(안티봇)보다 압도적으로 가벼움.

**구현·검증 완료** (`collect_11st_details.py`):
- 입력: 검색어 / `--codes` / `--from-json` 중 택1 → Open API로 상품 확보 → 각 상품 `view-desc`에서 상세 이미지 다운로드.
- 출력: `11st_output/details/{상품번호}/detail_NNN.*` (**쿠팡과 동일 구조** → 기존 VLM 판정 파이프라인 그대로 소비) + 매니페스트 JSON.
- 잡이미지(아이콘/버튼, 가로·세로 둘 다 <200px) 자동 제외.
- 검증: "다이어트 보조제" 검색 5/5 상품 상세 확보, 모두 2.2만~2.9만px 마케팅 통짜 이미지. 실제 과대광고 콘텐츠 확인("혈당컷 날씬다이어트" 등). 일부는 **광고심의번호** 노출 → 심의필/미필이 합법·위반 판정의 유용한 신호.
- 부수: 기존 `eleventh_st_crawler.py`의 디버그 `print(product)` leftover 제거.
