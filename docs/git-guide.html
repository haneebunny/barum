바름 Git 가이드 pull 받기 + 푸시 전 검증
환경 윈도우 + 맥 브랜치 docs/example-branch 원격 origin
pull→ 작업→ preflight→ add→ commit→ push

일 시작할 때 최신을 받고(pull), 끝내고 올리기 전에 검사한다(preflight). 검사를 통과해야 push.

A. 일 시작할 때: 최신 받기 (git pull)

남이 올린 변경을 먼저 받아두면 충돌이 줄어든다. 특히 윈도우와 맥을 오가며 작업하면, 다른 기기에서 올린 걸 먼저 받는 게 중요하다.

1. 내 변경부터 정리

먼저 지금 뭐가 바뀌었는지 본다.

git status   # 바뀐 파일 확인

바꾼 게 있으면 두 가지 중 하나로 정리한다. 커밋할 준비가 됐으면 커밋하고, 아직 아니면 잠시 보관한다.

# (준비됐으면) 커밋
git add -A
git commit -m "타입: 한 줄 설명"

# (아직이면) 임시 보관 후, pull 끝나고 되돌리기
git stash

2. 현재 브랜치 확인

git branch --show-current   # docs/example-branch 인지 확인

3. 최신 받기

git pull

현재 브랜치의 upstream이 origin/docs/example-branch으로 잡혀 있어서, 그냥 git pull이면 현재 브랜치 기준으로 받는다.

4. 보관해 뒀으면 되돌리기

git stash pop   # 1번에서 git stash 했을 때만

충돌(conflict)이 나면

같은 줄을 서로 다르게 고쳤을 때 충돌이 난다. 당황하지 말고 순서대로.

  1. git status로 충돌 난 파일을 확인한다.
  2. 그 파일을 열면 아래 표시가 있다. 표시 사이에서 남길 내용만 남기고 표시 줄은 지운다. 
    <<<<<<< 내 것
   ... 내가 고친 내용 ...
=======
   ... 받아온 내용 ...
>>>>>>> 상대 것
  3. 정리한 파일을 다시 올린다. 
    git add <정리한 파일>
git commit   # merge 메시지가 뜨면 그대로 저장
헷갈리면 멈추기
어느 쪽을 남길지 확신이 없으면 억지로 진행하지 말고 물어본다. 충돌 정리를 잘못하면 남의 작업이 사라질 수 있다.

B. 올리기 전에: 푸시 전 검증 (preflight)

비밀 유출(키, .env, 문서)과 깨진 코드를 올리기 전에 한 번에 잡는다. 이 검사는 git 명령을 대신 실행하지 않는다. 통과하면 마지막에 복사해서 쓸 명령을 보여준다.

1. 검사 실행

# 맥 / 리눅스
./preflight.sh

# 윈도우 PowerShell
.\preflight.ps1

배포 전이거나 프론트를 크게 바꿨으면 빌드까지 확인한다. 옵션은 두 OS 모두 --build로 같다.

./preflight.sh --build      # 맥
.\preflight.ps1 --build     # 윈도우

2. 결과 읽기

차단 (FAIL)
비밀 파일, 하드코딩 키, 민감 문서/대용량 데이터, 문법/lint/build/test 실패. 여기서 멈춘다. 사유를 고치고 다시 실행한다.
종료코드 1 · git 안내 안 뜸
경고 (WARN)
이메일 노출, 추적 안 된 민감 파일, 큰 파일. 막지는 않는다. 눈으로 확인만 하고 넘어간다.
종료코드 0 · 진행 가능
통과 (OK)
전부 통과하면 마지막에 아래 3번 git 명령이 그대로 출력된다. 복사해서 쓰면 된다.
종료코드 0 · git 안내 출력

3. 통과했으면 올리기

git add -A                       # 특정 파일만: git add <경로>
git commit -m "타입: 한 줄 설명"
git push

커밋 메시지 규칙: 한국어로, 접두어는 feat / fix / docs / chore / refactor 중 하나, 붙임표는 하이픈만 쓰고 em-dash는 쓰지 않는다. 예: git commit -m "docs: git 가이드 추가"

차단이 뜨면 절대 우회하지 말 것
비밀 파일이나 키가 잡혔는데도 억지로 올리면(예: git add로 강제 추가) 유출이 그대로 원격에 남는다. 한 번 올라간 비밀은 지워도 기록에 남으니, 차단은 반드시 원인을 없애고 다시 검사한다. 자세한 검사 항목과 오탐 처리는 docs/preflight.md 참고.
빨강은 "차단 / 절대 하지 말 것"에만. 나머지 상태는 글자로 표시. 기준 문서: docs/preflight.md
