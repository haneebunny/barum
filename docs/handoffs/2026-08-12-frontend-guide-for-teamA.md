## 1. 방향 잡기 (frontend-design 스킬 요지)

**목표: "어디서 본 듯한" 디폴트 느낌을 피하고, 이 제품다운 선택을 한다.**

- **주제에서 출발한다.** barum은 화장품 광고 컴플라이언스 검수 도구다. "탐지 → 근거 → 수정 → 생성"
  흐름 자체가 이 제품의 성격이다. 범용 SaaS 템플릿이 아니라 이 도메인의 어휘(판정·근거·위반·경보)에서
  비주얼 단서를 가져온다. (barum은 이미 "터미널/로그 감성 + 그린-블랙"으로 방향이 잠겨있음, DESIGN.md §1
  참조 — 바꾸지 말고 그 안에서 디테일을 채운다.)
- **타이포가 성격을 만든다.** 아무 화면에나 쓰는 폰트 조합 말고, 이 제품에 맞게 의도적으로 페어링한다.
  (barum은 Pretendard=사람 계층, JetBrains Mono=기계 계층으로 이미 확정, DESIGN.md §1.)
- **한 곳에만 과감해진다.** 시그니처 요소 하나(barum은 워드마크·터미널 모달·로그 스트림 같은 것)에
  힘을 주고, 나머지는 절제한다. 여러 군데서 튀려고 하면 산만해진다.
- **숫자 마커(01/02/03)는 실제 순서·프로세스일 때만** 쓴다. 장식으로 붙이지 않는다.
- **모션은 의도가 있을 때만.** 페이지 진입 시퀀스, 스크롤 리빌, 호버 마이크로인터랙션 등 "이게 왜
  움직이는지" 설명 가능해야 한다. 장식성 모션은 오히려 AI가 만든 티가 난다.
- **카피(문구)도 디자인 재료다.** 사람이 조작하는 대로 이름 붙인다("웹훅 설정"이 아니라 "알림 관리").
  능동태, 구체적 동사. 에러 메시지는 사과하지 않고 무엇이 잘못됐는지·어떻게 고치는지만 말한다.

## 2. 구체적 규칙 (ui-ux-pro-max + taste-skill 요지)

### 2.1 접근성 (최우선, 절대 스킵 금지)
- 본문/작은 글자 대비 **4.5:1 이상**, 큰 글자(18px+ 또는 14px+ 굵게) 3:1 이상.
- 포커스 링 항상 보이게 유지 (제거 금지). 키보드만으로 전체 조작 가능해야 함.
- 아이콘 전용 버튼엔 aria-label. 색만으로 의미 전달 금지 (아이콘·글자 병행).
- heading은 h1→h6 순서대로, 단계 건너뛰지 않음.

### 2.2 터치/인터랙션
- 클릭 가능한 요소 최소 44×44px, 요소 간 최소 8px 간격.
- hover에만 의존하는 인터랙션 금지 (클릭/탭이 기본).
- 비동기 작업 중엔 버튼 비활성화 + 로딩 표시.
- 클릭 가능한 요소엔 `cursor: pointer`.

### 2.3 레이아웃/반응형
- 모바일 우선 설계, 가로 스크롤 금지 (가로 스크롤이 "의도된 UI 요소"인 경우 제외).
- 브레이크포인트는 일관되게(예: 375/768/1024/1440).
- 데스크톱 컨테이너는 일관된 max-width 유지.
- z-index는 스케일 정해두고 씀(0/10/20/40/100/1000 식), 임의값 남발 금지.
- 여백/패딩은 수학적으로 정확하게. 애매하게 뜬 요소 없이.

### 2.4 타이포·색
- 본문 기본 16px, 줄간격 1.5~1.75.
- 색은 시맨틱 토큰으로만 쓴다 (컴포넌트 안에 raw hex 금지). barum은 CSS 변수로 강제(DESIGN.md §3.5).
- 데이터/가격/타이머는 tabular figure(고정폭 숫자) 사용.
- 기능색(에러·성공 등)은 항상 아이콘/글자 동반, 색 단독 금지.

### 2.5 애니메이션
- 마이크로인터랙션 150~300ms, 복잡한 전환도 400ms 이하.
- `transform`/`opacity`만 애니메이션 (width/height/top/left 애니메이션 금지, 리플로우 유발).
- 화면당 핵심 요소 1~2개만 움직인다. 전부 다 움직이면 산만함.
- `prefers-reduced-motion` 존중 (요청 시 모션 줄이거나 끔).
- 진입은 ease-out, 퇴장은 ease-in. linear는 UI 전환에 쓰지 않음.

### 2.6 폼/피드백
- label은 항상 보이게(placeholder를 label 대신 쓰지 않음).
- 에러는 해당 필드 옆에, 상단에 몰아서 띄우지 않음.
- 헬퍼 텍스트로 미리 안내, 한번에 너무 많은 정보 쏟아붓지 않음(단계적 공개).

## 3. 하지 말 것 (taste-skill "AI-tell" 요지, 커밋 전 훑기)

이 항목들은 "AI가 만든 티" 나는 패턴이라 명시적으로 요청받지 않는 한 피한다.

**비주얼**
- 네온/아웃라인 글로우 금지. 순수 검정(`#000000`) 금지 (off-black 사용).
- 과채도 강조색 금지 (뉴트럴과 어울리게 디새추레이트).
- 커스텀 마우스 커서 금지 (구식이고 접근성·성능에도 안 좋음).

**타이포**
- 아무 이유 없이 Inter를 기본으로 쓰지 않는다.
- 과장된 크기의 H1로 소리 지르지 않는다. 위계는 크기가 아니라 굵기+색으로.

**레이아웃**
- **똑같이 생긴 3열 카드(feature row) 금지.** 제일 흔한 "생성형 AI 느낌" 신호. 비대칭 그리드나
  지그재그 2열 등으로 바꾼다.

**콘텐츠/데이터**
- "John Doe" 류 뻔한 이름, 뻔한 아바타 아이콘(달걀 SVG, Lucide 사람 아이콘) 금지.
- 너무 완벽한 숫자(`99.99%`, `50%`) 금지. 실제스러운 지저분한 숫자 사용(`47.2%`).
- "Acme", "Nexus" 같은 스타트업 슬롭 브랜드명 금지.
- "Elevate", "Unleash", "Revolutionize" 같은 필러 동사 금지, 구체적 동사만.

**외부 리소스/컴포넌트**
- 손그림 SVG 아이콘 지양, 아이콘 세트 하나로 일관되게 (barum은 라인아이콘→Phosphor 전환 예정,
  DESIGN.md §5 참조).
- `<div>`로 가짜 스크린샷/가짜 대시보드 만들지 않는다. 실제 이미지나 실제 컴포넌트를 쓴다.
- 깨지는 Unsplash 링크 대신 `picsum.photos/seed/{설명}/{w}/{h}` 같은 안정적 플레이스홀더.

**마이크로카피/장식 패턴 (자잘하지만 흔함)**
- 섹션 번호 에이브로우(`00 / INDEX`, `001 · Capabilities`) 금지, 그냥 주제를 평범하게 말한다.
- 가운뎃점(`·`)을 만능 구분자로 남발하지 않는다 (줄당 최대 1개).
- **em-dash(—) 절대 금지.** (barum CLAUDE.md 전역 규칙과 동일, 이 프로젝트에서 특히 엄격.)
- `<br>`로 끊고 기울임 넣는 "for thirty\<br\>*years.*" 식 헤드라인 연출 지양.
- 회전된 세로 텍스트, 장식용 크로스헤어/그리드선 지양 (실제 내용을 조직하는 용도가 아니면).
