## 0. 이번 세션에서 한 일

가이드북 C-4/C-5 과제: ② 현 파이프라인(OCR→판정) vs ③ 한 방(VLM 이미지 통째 판정) 비교 실험.

**구현**: `backend/scripts/compare_ocr.py` (신규, 미커밋 상태일 수 있음 — `git status` 확인)
- `--dry` : 배선 점검
- `--only pipeline` / `--only oneshot` : 방식별 단독 실행
- `--oneshot-rag` : ③에 규정문서+사례 근거(`build_judgment_context()`)를 붙여서 실행
- `--token-breakdown` : ②를 OCR 단계·판정 단계로 나눠 토큰/시간 계측 (규칙 확정 vs GPT 위임 비율도 같이 잼)

**정답셋**: `backend/11st_probe_cosmetic/read_test/label_worksheet.xlsx` (대수 라벨 초안, **하니 검수 전, 잠정**)

## 1. 실험 결과 (잠정 — 14장, 위반 15건 기준)

| 항목 | ② 나눠서 | ③ RAG 없음 | ③ +RAG |
|---|---|---|---|
| 정탐/미탐/오탐 | 14/1/23 | 13/2/16 | 13/2/13 |
| 탐지율 | 93.3% | 86.7% | 86.7% |
| 토큰(14장 합) | 398,838 | 70,904 | 280,404 |

결론: 미탐 최소화(프로젝트 1순위 지표) 기준으론 ②가 우세하나 토큰이 5.6배. 표본이 작고(14장) 정답셋이 잠정이라 확정적 결론은 아님.

## 2. 토큰 분석 (`--token-breakdown` 결과)

②의 토큰이 어디서 새는지 나눠봤다.

| 항목 | 값 |
|---|---|
| OCR 토큰 | 33,473 (9.6%) |
| 판정(GPT+RAG) 토큰 | **317,006 (90.4%)** |
| 규칙집 무료 확정 | 12개 / 155문장 (**7.7%**) |
| GPT 위임 | 143개 / 155문장 (**92.3%**) |

**원인 분석 (핵심 발견)**: 정답셋 240문장 라벨 분포를 보면 **대상외 69.6% + 합법 22.9% = 92.5%** — GPT 위임률 92.3%와 거의 정확히 일치한다.

`backend/src/barum/reference/rules.py`의 `RuleOutcome` enum은 `violation`/`needs_review`/`legal_allow` **3갈래뿐이고 `out_of_scope`(대상외) 갈래가 아예 없다.** `judge_rules.json`도 대상외 키워드/패턴이 없다. `legal_allow`도 키워드 3개(탄력/민감/예민)뿐이라 커버리지가 거의 없다.

→ **위반 판정용 키워드(1호 37개+4개, needs_review 9개)는 촘촘한 편.** 문제는 "이건 위반이 아니다"를 무료로 확정하는 쪽이 구조적으로 없다는 것. 정보(키워드) 부족이 아니라 **로직 설계의 공백**이 근본 원인.

## 3. 다음 할 일 (사용자가 동의한 3가지, 우선순위 순)

1. **`RuleOutcome`에 `out_of_scope` 갈래 추가** (`reference/rules.py`)
   - `violation` / `needs_review` / `legal_allow` 옆에 `out_of_scope` 추가
   - `RagJudge.judge()`에서 `out_of_scope` 매칭 시 finding 안 만들고 VLM에도 안 넘기는 처리 추가 (지금 `legal_allow` 처리와 동일한 패턴)

2. **`judge_rules.json`에 대상외 패턴 채우기**
   - 정답셋(`label_worksheet.xlsx`)의 대상외 167건을 훑어서 패턴 추출 필요 (예: 성분명 나열 형식, 인증서·거래정보 문구, 브랜드명/용량 표기 등)
   - 단순 키워드 매칭으로 안 될 수도 있음 (예: 성분 나열은 "쉼표로 구분된 명사 나열" 같은 패턴 감지가 필요할 수 있어 정규식/휴리스틱 설계 필요) — **착수 전 대수 인터뷰 필요** (CLAUDE.md A/B 규칙: 코드 전 인터뷰, 단계별 계획 승인 후 진행)

3. **`legal_allow` 키워드 목록 확대**
   - 지금 3개(탄력/민감/예민)뿐. 정답셋 합법 55건에서 패턴 추출해 확장

**주의**: 이 세 가지를 다 하면 GPT 위임률이 크게 줄어 토큰 비용이 상당히 절감될 것으로 예상되지만, 정답셋이 잠정(하니 검수 전)이라 규칙 확장 후 실측 재검증 필요.

## 4. 참고: 이번 세션에서 나온 다른 논의 (착수 안 함, 참고만)

- **아키텍처 제안 검토**: "LLM이 먼저 호수 분류 → 호수별 RAG 개입" 라우터 구조 제안 있었음. 검토 결과 코퍼스가 작아(규정문서 전체 350줄 안팎) 선택적 검색의 이득이 크지 않고, 콜 수 2배(비용 증가)에 분류오류 전파 위험도 있어 **보류 권고**. 레퍼런스팩 준비도: 1호/2호는 됨, **5호는 "일반 수식어" 판정기준 자체가 미확정**(`violation_types/type_5_deception.md` 참조), 대상외는 전용 레퍼런스 파일 없음.
- **2호(기능성오인) 판정 한계**: 기능성화장품 인증 3요건(이름/함량/실제등록) 중 이름만 자동 대조 중. 함량(전성분표에 %없음)·실제등록(식약처 DB 없음)은 미구현. 별도 과제로 남겨둠.
