## 하니 확정 결정 (되돌리지 말 것)
- 화장품 위반유형 = 개정법 기준 5호. 위반/검토필요 이진 플래그.
- RAG = 규칙 우선 + 문서 인라인, 벡터검색은 실사례 유사도 매칭에만.
- DB = Supabase(이력+증거보존, 로그인 없이 추측불가 result_id).
- **v1.9**: 화면 5개, 요금제 확정(Free 0원·Basic 4.9만원·Pro 14.9만원·Export 애드온 건당 4.9만원), 수정권고안은 Basic부터, 인증·결제는 MVP 범위 밖.
- **FR-14/FR-11 설계**: 자유생성 아닌 결정론적 템플릿/조건표 치환. 효능표현은 항상 근거(조건표 또는 인정문구) 기반, LLM이 새로 짓지 않음.
- **FR-14 티어 게이팅**: 프론트 전용 토글(백엔드 무변경).
- **콘텐츠생성 내보내기**: HTML/PNG/PDF 프론트 클라이언트, Figma 제외.
- **판정 AI 모델**: GPT-5-mini 유지(judge·generate 공통). 비용 문제 없음(요청당 10~20원대).
- **모공수축/모공축소**: T5(거짓·과장) 준용, 실증자료 없으면 검토필요·있으면 예외.
- PR 머지는 하니만. PM은 계획 승인·코드리뷰까지.

## git · 규칙
- 기준 브랜치 `main`. `gh` CLI 없음, push 후 뜨는 PR 링크를 하니가 웹에서 열어야 함.
- **여러 세션이 같은 메인 워크트리를 공유한다.** `git add .`·`-A` 금지, 파일 지정만. 남의 파일 스테이징 금지.
- **메인 워크트리에서 절대 `git checkout <다른 브랜치>` 하지 말 것.** 브랜치 작업은 항상 `git worktree add <임시경로> -b <브랜치> origin/main`으로 격리 후 끝나면 `git worktree remove`.
- **PM도 절대 main에 직접 push 안 함.** "push해줘"도 브랜치+PR로 이해한다(예외로 한 번 어긴 적 있음, 재발 금지).
- **origin에서 브랜치가 갑자기 여러 개 사라져도 사고 아닐 수 있다.** "PR 머지 시 head 브랜치 자동삭제" 설정 때문. `git merge-base --is-ancestor <SHA> origin/main`로 이미 main에 들어갔는지 먼저 확인(2026-08-12 밤 실제 오탐 있었음, CLAUDE.md §G 참조).
- 키는 `backend/.env`(gitignore): 전부 설정 완료.
