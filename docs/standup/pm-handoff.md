# PM 세션 인수인계 (barum)

> 새 PM 세션은 이 파일부터 읽고 이어받는다. 상세는 아래 참조 문서.
> 역할: PM = 하니(총괄/개발리드) 조율. 구현은 각 세션에 위임. **오너십: 하니 착수(결정) → 담당 실행 → 하니 검수.**

- 화면 4개(v1.7부터 콘텐츠생성 추가): 홈 · 새 검사 · 결과 리포트 · 콘텐츠 생성.
- 참조: `ROADMAP.md`(⚠**아직 v1.5, 갱신 안 됨** — 아래 "다음 우선순위" 참조), `PROJECT.md`(확정 결정, 일부 최신 상태 반영 안 됐을 수 있음 재확인 권장), `CLAUDE.md`(작업규칙), `AGENTS.md`(git 규칙), `docs/handoffs/`, `docs/standup/`.

## 팀 · 세션 (relay = mcp__ccd_session_mgmt__send_message, session_id는 list_sessions로 재확인할 것 — 세션 자주 바뀜)
- **정빈** = 프론트·디자인 · **대수** = 백엔드 · **하니** = 총괄/개발리드.
- 세션 이름은 계속 바뀐다("백엔드 1 (구)"→"백엔드 2 (현)" 식). **매번 `list_sessions`로 "(현)" 붙은 최신 세션 찾아서 relay할 것.** 이름만 보고 예전 session_id 재사용하면 죽은 세션에 말 건다.
- **주의(실제 있었던 사고)**: PM 세션이 여러 개 존재할 수 있다("PM 1"·"PM 2"). 다른 세션이 relay 메시지 출처("PM 2" 등)를 의심할 수 있으니, 모호하면 `list_sessions`로 자기 자신을 포함해 확인하고 명확히 밝힐 것.

## git · 규칙
- 기준 브랜치는 이제 `main`(v1.4-pivot 아님). origin = `github.com/haneebunny/barum.git`.
- **여러 세션이 같은 워크트리를 공유한다.** `git add .` 절대 금지, 파일 지정해서만. 이번 세션에 실수로 남의 파일 같이 커밋한 사고 1건 있었음(데이터 유실은 없었음).
- `gh` CLI 없음(PM도 백엔드도). PR 생성 링크(`.../pull/new/<브랜치>`)를 하니가 웹에서 열어야 함.
- 브랜치 스택(A가 B 위에 얹힌 구조) 머지 시 생성파일(openapi.json·fixtures)이나 같은 자리에 각자 추가한 테스트/import가 충돌날 수 있다 — **로직 충돌은 거의 없었다, 대부분 기계적으로 풀림.** PM이 로컬에서 `git merge-tree`로 먼저 확인하고 필요시 직접 정리해서 브랜치에 푸시하는 방식으로 두 번 처리함(머지 버튼은 안 누름).
- 키는 `backend/.env`(gitignore됨): `GOOGLE_API_KEY`(OCR)·`OPENAI_API_KEY`(판정)·`SUPABASE_URL`·`SUPABASE_KEY`(secret/service_role, anon 아님) 전부 설정 완료.
