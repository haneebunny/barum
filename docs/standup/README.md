# 일일 리포트 시스템 설계 (v0)

> **상태:** 설계 확정, **자동발송 보류**(Slack 커넥터 미연결). 지금은 문서 산출까지. Slack 연결되면 동일 내용을 자동발송으로 켠다.
> **작성일:** 2026-08-07 · 담당: PM(Claude)

---

## 1. 목적

- **오전 09:00 KST:** 그날 각자 할 일을 로드맵 기준으로 정리한 **오전 플랜**.
- **저녁 19:00 KST:** 어디까지 갔는지, 뭐가 막혔는지 **진행 리포트**.
- 총괄/개발리드(하니)가 진행상황을 한눈에 보고, 크리티컬 패스가 안 막히게 조율.

## 2. 팀 · 워크스트림

| 스트림 | 영역 | 담당 |
|---|---|---|
| **A** | 백엔드 / 데이터 (라벨→DB→학습셋), **크리티컬 패스** | 대수 |
| **B** | DL 코어 ① 문장 분류기 | 미정 |
| **C** | 프론트엔드 (웹 콘솔) | 정빈 |

- **하니 = 총괄 / 개발리드.** 특정 스트림 소유가 아니라 전체 조율·의사결정. (예: DL 학습소스, A/B 병합 규칙 등 결정권자.)
- **B(DL) 담당 미정** → 정해지면 이 표와 `status.md` 갱신.

## 3. 스케줄 (메커니즘 = 스케줄 루틴/cron)

| 루틴 | 시각(KST) | 하는 일 |
|---|---|---|
| 오전 플래너 | **09:00** | 로드맵·핸드오프·repo 상태·미해결 블로커를 읽어 그날 플랜 생성 → 그날 파일에 기록 |
| 저녁 리포터 | **19:00** | 하루 변화(§4)를 합성해 진행 리포트 생성 → 그날 파일에 기록 |

> 지금은 **미생성**. Slack 연결 시 이 두 루틴을 만들고, 산출물을 파일 기록 + Slack 발송 둘 다 하도록 켠다.

## 4. 진행 판단 소스 (자동 + 수동 병행)

저녁 리포터는 아래를 합성한다:
1. **repo 상태 자동:** 그날 생성·수정된 파일, `git log`(git init 후), 핸드오프 §7 완료기준 체크박스 상태.
2. **상태 파일 수동:** 각 담당이 `docs/standup/status.md`에 **자기 스트림 한 줄**을 갱신(지금 하는 일 / 막힌 것). "왜 막혔는지" 같은 맥락은 자동으로 못 잡으니 이 줄로 보완.

## 5. 산출물 · 저장 규약

```
docs/standup/
├─ README.md              (이 설계 문서)
├─ status.md             (팀원 현재 상태 보드, 각자 한 줄, 수시 갱신)
└─ YYYY-MM-DD.md         (하루 1파일: 오전 플랜 + 저녁 리포트)
```

### 오전 플랜 템플릿 (`YYYY-MM-DD.md`의 상단)

```
- ...

- ...
```
