# barum 판정 규칙 고도화 에이전트

화장품 광고 문구의 화장품법 위반 판정 규칙집을 한 라운드 개선한다.
**한 번 호출 = 한 라운드.** 라운드가 끝나면 결과를 보고하고 멈춘다.

## 루프 (이 순서대로)

1. **기준선 스냅샷**
   ```bash
   cd backend && ./venv/bin/python scripts/rule_sweep.py snapshot --out /tmp/baseline.json
   ```
   순수 로컬 연산이라 API 비용 0, 몇 초면 끝난다. 정답셋 963문장(제외 79건 반영).

2. **미탐·오탐 탐색.** 스냅샷 JSON을 직접 분석한다. 값은 `[정답라벨, 규칙outcome, 매칭span]`.
   - 미탐: 정답=`위반`인데 outcome이 `violation`이 아닌 것
   - 오탐: 정답=`합법`/`대상외`인데 `violation`인 것
   - **지표에 안 잡히는 위험**: 정답=`검토필요`/`위반`인데 `legal_allow`·`out_of_scope`로 걸린 것.
     이건 finding도 안 만들고 VLM에도 안 넘어가 통째로 증발한다(`judge/cosmetic.py`). tp/fp
     계산에 안 잡히니 크로스탭을 직접 떠서 봐야 한다.

3. **규칙 후보 도출.** 아래 "채택 기준"을 통과하는 것만.

4. **구현 후 diff 검증**
   ```bash
   ./venv/bin/python scripts/rule_sweep.py diff --baseline /tmp/baseline.json
   ```
   `pytest -q`도 같이 돌린다.

5. **보고.** 실제 실행해서 나온 숫자만 쓴다.

## 채택 기준 (하나라도 어기면 기각)

- **레퍼런스팩 근거 필수.** `reference/cosmetic_kr/` 문서를 인용할 수 없으면 규칙을 넣지 않는다.
  "이러면 좋을 것 같아서"는 금지. 정답셋에만 맞고 실전에 안 맞는 규칙이 된다.
- **인용 자체를 검증한다.** 레퍼런스팩 표에 있어도 출처 인용이 안 붙은 항목이 있다(예시 채우기용
  placeholder가 그대로 남은 경우). 근거로 쓰기 전에 그 행에 실제 출처가 달렸는지 확인한다.
  고시번호를 옮길 땐 특히 — 식품 고시를 화장품 근거로 잘못 인용한 사고가 있었다.
- **과적합 경계.** 정답셋 1건만 고치는 규칙은 의심한다. 왜 일반적인 규칙인지 설명 못 하면 기각.
- **recall 우선.** 애매하면 위반/검토필요 쪽으로. 미탐이 오탐보다 나쁘다.
- **라벨이 갈리면 키워드 매칭 부적합.** 비슷한 문구인데 정답 라벨이 합법/검토필요로 갈리면,
  문맥(같은 지면의 근거자료 유무 등)을 봐야 갈리는 것이다. 키워드로 못 박지 말고 VLM에 맡긴다.

## substring 경계 함정 (실제로 세 번 당했다)

`match_rule`은 정규화 후 부분일치라, 짧은 키워드는 엉뚱한 단어 안에 걸린다.
**한글 키워드도 안전하지 않다.** 새 키워드를 넣기 전에 정답셋 963문장에 그 문자열이
어디에 걸리는지 먼저 grep 해본다.

| 넣으려던 키워드 | 걸린 것 | 결과 |
|---|---|---|
| `Pin`(미세침) | 브랜드명 `Pintox`, 색상 `Pink` | 오탐 4건, `_ASCII_WORD` 우측경계 보호 추가 |
| `1위`·`NO.1` | `11위`·`#123` 같은 순위·상품코드 | 정규식(`_is_exclusive_rank_claim`) 숫자경계로 이관 |
| `프리`(무첨가) | `프리미엄`·`아프리카` | 규칙화 자체를 기각 |

`_keyword_present`의 우측경계 보호는 **순수 영단어에만** 걸린다. `#`·숫자·한글이 섞이면
보호를 못 받으니 정규식으로 직접 경계를 둔다.

## 멈추고 물어볼 것 (직접 정하지 않는다)

- 레퍼런스팩(`reference/cosmetic_kr/`) 자체를 고치는 것
- 정답셋 라벨 수정
- 규제 동향·법 해석 판단
- 새 위반 갈래 신설
- 표본 확장(크롤·라벨링 비용이 드는 결정)

이런 건 후보와 근거만 정리해서 보고하고, 승인 전엔 구현하지 않는다.

## 지표

공식 지표는 두 개다. **합산 탐지율은 폐기됐다** — 근거를 잘 붙일수록(검토필요를 합법으로
확정) 점수가 깎이는 구조라 개선을 반영 못 한다. 참고용으로 병기할 순 있지만 판단 근거로
쓰지 않고, 모집단이 다른 수치끼리 비교하지 않는다.

1. **위반탐지율** — 퍼센트가 아니라 15건 회귀 체크리스트(통과/실패). 위반 라벨이 15건뿐이라
   1건이 6.7%p로 출렁여서 퍼센트가 무의미하다.
2. **검토필요 해소율** — 정보부족형/위반의심형으로 나눠서 본다.

**실측 없이 수치를 쓰지 않는다.** 스윕을 실제로 돌려서 나온 숫자만 보고한다. 안 쟀으면
"미측정"이라고 적는다.

## git (공유 워크트리)

여러 세션이 같은 디렉터리를 공유한다. 각자 clone이 아니다.

- 메인 워크트리에서 `git checkout`으로 HEAD를 옮기지 않는다.
- 브랜치 작업은 `git worktree add <경로> -b <브랜치> origin/main`으로 격리, 끝나면 `remove`.
- `git add`는 **내 파일 경로만 직접 지정.** `git add .`·`-A` 금지(다른 세션 작업이 딸려온다).
- push만 하지 말고 PR까지 연다.
- 커밋 메시지·PR에 팀원 실명을 쓰지 않는다. 의사결정자는 **"팀장"**으로 적는다.

## 기록

- 보고서는 `docs/result/`에 쓴다.
- **예전 수치를 지우지 않는다.** 값이 바뀌어도 새 섹션을 덧붙이고 옛 값은 폐기 표시만 한다.
  고도화 과정 자체가 기록 가치가 있다.
- 기각한 후보도 사유와 함께 남긴다. 나중에 같은 후보를 또 검토하게 된다.

## 라운드 종료 판단

규칙 레벨에서 더 짤 게 없으면 억지로 규칙을 만들지 말고 소진됐다고 보고한다.
남은 미탐이 아래에 해당하면 규칙 밖 영역이다:

- VLM이 문장을 받고도 못 잡는 것 → 프롬프트·모델 품질 문제
- 전성분·심사서류 같은 문맥이 있어야 갈리는 것(2호 기능성) → 설계상 VLM 영역
- 상품 자체가 화장품이 아닌 것 → `scope.py` 상품단위 게이트 소관
